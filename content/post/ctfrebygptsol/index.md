## 阅读约定与路线

### 全文统一约定

- **架构**：x86-64，也叫 AMD64 或 x64。

- **主线环境**：Linux 的 ELF 可执行文件格式 + System V AMD64 ABI。ABI（应用二进制接口）规定函数怎样传参、类型怎样布局以及不同机器代码怎样协作。

## 0. 先建立最小的底层模型

你不需要从晶体管或逻辑门学起。为了逆向，只要先接受一个足够准确的模型。

### 0.1 从源码到正在运行的程序

写下：

```cpp
int add(int a, int b) {
    return a + b;
}
```

大致会经历：

```text
C/C++ 源码
   │  编译器：翻译并优化
   ▼
汇编 / 机器指令
   │  汇编器、链接器：生成可执行文件并连接外部函数
   ▼
磁盘上的 ELF 或 PE 文件
   │  操作系统加载器：映射代码和数据，准备栈与依赖库
   ▼
进程：拥有自己的虚拟地址空间和一组正在变化的 CPU 状态
```

几个词不要混淆：

- **汇编语言**是机器指令便于人阅读的文字表示，如 `add eax, esi`；
- **机器码**是 CPU 实际读取的字节，如某条指令可能编码为 `01 f0`；
- **反汇编**是从机器码恢复汇编；
- **反编译**是继续猜测更高层的 C 风格伪代码；
- 反编译器恢复的是“可能的表达方式”，通常恢复不了原变量名、注释和完全相同的源码。

### 0.2 运行中的程序：寄存器、内存、RIP、RFLAGS

逆向一段普通用户态代码时，可以把 CPU 想成不断重复：

1. 从 `RIP` 指向的位置取出下一条指令；
2. 读取这条指令需要的寄存器或内存；
3. 进行运算；
4. 把结果写回寄存器或内存；
5. 更新 `RIP`，必要时更新 `RFLAGS` 中的条件标志。

程序在某一瞬间的关键状态可简化为：

```text
寄存器：少量、很快、直接参与运算的存储位置
内存：  很大的按字节编号的空间
RIP：   下一条要执行的指令地址
RFLAGS：最近一次相关运算留下的条件信息
```

**汇编不是神秘公式，而是一连串状态变化。** 阅读汇编时，始终问：

> 这条指令读了什么？写了什么？下一条执行谁？

### 0.3 变量名和类型会怎样

源码中的：

```cpp
int score = 100;
```

在优化后的机器代码里未必还有名为 `score` 的东西。它可能：

- 暂时放在某个寄存器里；
- 放在栈上的 4 个字节里；
- 被编译器算成常量后彻底消失；
- 在不同时间复用不同位置。

CPU 通常只看到“某处的若干位”和“对这些位执行何种宽度、何种语义的操作”。`int`、指针、数组等类型主要是源码和编译器的概念；逆向时，类型常常需要从访问宽度、运算和使用方式反推。

## 1. 字节、十六进制与数据解释

### 1.1 位、字节和十六进制

- 1 bit（位）只能是 `0` 或 `1`；
- 1 byte（字节）通常是 8 bit；
- 1 个十六进制数字表示 4 bit；
- 所以 2 个十六进制数字正好表示 1 字节。

```text
二进制  1101 0110
十六进制   D    6     → 0xD6
```

常见范围：

| 宽度 | 位数 | 十六进制位数 | 无符号范围 |
|---|---:|---:|---:|
| byte | 8 | 2 | 0 到 255 |
| word | 16 | 4 | 0 到 65,535 |
| dword | 32 | 8 | 0 到 2³²−1 |
| qword | 64 | 16 | 0 到 2⁶⁴−1 |

逆向工具常用十六进制，因为它比二进制短，又能自然按字节分组。`0x401050` 是数值的十六进制写法，不要把前缀 `0x` 算进数字。

### 1.2 位模式没有自带含义

一个字节 `0x41` 可以被解释成：

- 无符号整数 `65`；
- 有符号整数 `65`；
- 常见字符编码 ASCII 中的字符 `'A'`；
- 某条机器指令的一部分；
- 某个大整数的一部分。

含义来自**上下文**：访问了几字节、使用哪条指令、之后怎样使用结果。反编译器显示的类型只是依据上下文作出的推断。

### 1.3 无符号、有符号与补码

8 位的 `1111 1111`：

- 按 `unsigned char` 解释是 `255`；
- 按常见的二进制补码 `signed char` 解释是 `-1`。

位并没有变化，变化的是解释规则。对 n 位补码数：最高位为 0 时和普通二进制一样；最高位为 1 时，其有符号值等于无符号值减去 $2^n$。

例如：

```text
0xFE 的无符号值 = 254
0xFE 的 8 位有符号值 = 254 - 256 = -2
```

这会直接影响：

- 扩展到更宽数据时补 `0` 还是补符号位；
- 比较时用 `ja/jb` 还是 `jg/jl`；
- 右移时用 `shr` 还是 `sar`；
- 除法时用 `div` 还是 `idiv`。

### 1.4 截断、溢出与模 $2^n$

8 位位置只能保留最低 8 位：

```text
0xFF + 1 = 0x100
只保留 8 位后得到 0x00
```

机器级运算经常自然呈现“模 $2^n$”效果。但映射回 C/C++ 时要谨慎：无符号整数的回绕有明确定义；有符号溢出在 C/C++ 中通常属于未定义行为，也就是语言标准不规定结果，优化器可假设合法程序不会触发它并据此改写代码。

### 1.5 小端序：多字节值怎样放进内存

x86-64 使用小端序。若 32 位整数：

```text
x = 0x12345678
```

从低地址到高地址的四个字节是：

```text
地址       0x1000  0x1001  0x1002  0x1003
内容         78      56      34      12
```

“低有效字节”放在低地址。调试器若按字节显示会看到 `78 56 34 12`，按 4 字节整数显示仍会得到 `0x12345678`。

小端序不会把字符串整体倒过来。字符串 `"ABC"` 仍按地址递增存放：

```text
41 42 43 00
 A  B  C \0
```

### 1.6 固定宽度整数与 `size_t`

C/C++ 的 `long` 在不同平台不一定同宽：许多 64 位 Linux 环境中它是 8 字节，而 Windows x64 中仍常是 4 字节。为了讨论机器宽度，本文优先使用 `<stdint.h>` / `<cstdint>` 中的固定宽度整数；`size_t` 则由 `<stddef.h>` / `<cstddef>` 等标准头提供：

| 类型 | 含义 |
|---|---|
| `uint8_t` / `int8_t` | 无符号 / 有符号 8 位整数 |
| `uint16_t` / `int16_t` | 16 位整数 |
| `uint32_t` / `int32_t` | 32 位整数 |
| `uint64_t` / `int64_t` | 64 位整数 |
| `size_t` | 表示对象大小和计数的无符号整数类型，x86-64 常见 ABI 中通常为 64 位 |
| `uintptr_t` | 若实现提供，可容纳转换后对象指针值的无符号整数类型 |

固定宽度名字能减少教程示例的歧义，但并不会让任意整数与指针转换自动变得合理。

### 1.7 本章检查点

1. `0x7A` 占几个字节？
2. 内存从低地址开始是 `34 12 00 00`，按小端 32 位整数读取是多少？
3. 一个字节 `0xFF` 是 `255` 还是 `-1`？

答案：1 字节；`0x00001234`；第三问必须先知道采用有符号还是无符号解释。

## 2. 第一段 x86-64 汇编

先只观察一个**不涉及函数、栈和调用约定**的状态片段。高层意图是：

```cpp
int x = 3;
int y = 4;
int result = (x + y) * 2;
```

`eax`、`ecx` 暂时理解成两个能保存 32 位数的工作位置；下一章再讲它们和 `rax/rcx` 的关系：

```asm
mov eax, 3          ; eax = 3
mov ecx, 4          ; ecx = 4
add eax, ecx        ; eax = 3 + 4
add eax, eax        ; eax = 2 * (3 + 4)
```

Intel 语法最重要的阅读规则：

```text
mov 目的, 源       ; 目的 = 源
add 目的, 源       ; 目的 = 目的 + 源
sub 目的, 源       ; 目的 = 目的 - 源
```

因此 `mov eax, 3` 把直接写在指令里的常量 3 复制到 `eax`。`mov` 通常是复制，源位置本身不会被“搬空”。

可以用一个状态表跟踪：

| 时刻 | `eax` | `ecx` |
|---|---:|---:|
| 开始 | 未知 | 未知 |
| `mov eax, 3` 后 | 3 | 未知 |
| `mov ecx, 4` 后 | 3 | 4 |
| 第一次 `add` 后 | 7 | 4 |
| 第二次 `add` 后 | 14 | 4 |

这就是最基础的**手工状态追踪**：不用真的运行，也能在纸上逐条更新状态。严格意义的“符号执行”会让输入保持为符号表达式并维护路径约束，不是这里用具体数字演算的同义词。

小检查：若改成 `mov eax, 5; mov ecx, 2; sub eax, ecx; add eax, eax`，最终 `eax` 是 6。先自己按表格写一遍，再继续。

> 同一段 C/C++ 可能产生不同汇编。编译器、版本、优化级别和上下文都会影响结果。逆向需要识别等价语义，而不是背某一份固定模板。

## 3. 寄存器：CPU 手边的工作位置

### 3.1 通用寄存器

x86-64 常见的 16 个通用整数寄存器：

```text
RAX RBX RCX RDX RSI RDI RBP RSP
R8  R9  R10 R11 R12 R13 R14 R15
```

它们都能保存 64 位数据。名字中的“通用”意味着不要给它们强行绑定永久含义。某一时刻 `RAX` 可能是返回值，下一段代码里也可能是临时数、地址或循环计算结果。真正的用途由指令和调用约定决定。

几个特殊角色：

- `RIP`：指令指针，决定下一条执行位置；
- `RSP`：栈顶指针；
- `RBP`：普通寄存器，但未优化代码常把它用作栈帧基准；
- `RFLAGS`：保存零、进位、溢出等条件标志。

### 3.2 同一个寄存器的不同宽度

`RAX` 的低位可以用不同名称访问：

```text
位号：63                       32 31               16 15        8 7         0
RAX ：[---------------------------完整 64 位-------------------------------]
EAX ：                                  [-----------低 32 位--------------]
 AX ：                                                      [---低 16 位---]
 AH ：                                                      [15......8]
 AL ：                                                                 [7..0]
```

更准确地说：

| 宽度 | 常见名字 | 含义 |
|---:|---|---|
| 64 位 | `rax` | 完整 64 位 |
| 32 位 | `eax` | `rax` 的低 32 位 |
| 16 位 | `ax` | `rax` 的低 16 位 |
| 8 位 | `al` | `rax` 的低 8 位 |

其他传统寄存器也有类似名字：`rbx/ebx/bx/bl`、`rcx/ecx/cx/cl` 等；`r8` 则使用 `r8d/r8w/r8b`。

### 3.3 必须记住的规则：写 32 位会清高 32 位

在 x86-64 中：

```asm
mov eax, 1
```

执行后整个 `rax` 是 `0x0000000000000001`。写入 `eax` 会自动把 `rax` 的高 32 位清零。

但写 `ax` 或 `al` 不会自动清除其余位：

```asm
; 假设 rax = 0x1122334455667788
mov al, 0xFF
; 结果 rax = 0x11223344556677FF
```

所以看到 `xor eax, eax` 时，它常用于把完整 `rax` 清零：

```asm
xor eax, eax        ; eax = 0，因此 rax 也变成 0
```

### 3.4 寄存器没有类型

假设 `rax = 0x0000000000401000`。它可能表示：

- 十进制整数；
- 某个对象的地址；
- 函数地址；
- 位掩码。

只有后续行为能提供证据。例如 `mov ecx, [rax]` 把它当作地址使用；`call rax` 把它当作函数入口使用；`add rax, 5` 单独看则无法确定。

## 4. 内存、地址与指针：从零讲清

这是整篇教程最关键的一章。后面的 `[...]`、数组、栈、结构体和虚函数都建立在这里。

### 4.1 内存是一排带编号的字节格子

可以把进程可见的虚拟内存想象成一排字节：

```text
地址       0x1000  0x1001  0x1002  0x1003  0x1004  ...
内容         ??      ??      ??      ??      ??
```

每个格子：

- 有唯一地址；
- 保存 1 字节；
- 多字节对象占据连续多个格子。

一个常见的 32 位 `int` 占 4 字节。如果 `x` 从地址 `0x1000` 开始，`x` 覆盖 `0x1000` 到 `0x1003`。

这里说的是**虚拟地址**。操作系统为每个进程维护地址空间和映射；普通逆向初期不必追到物理内存。指针里通常装的是进程虚拟地址。

### 4.2 三件事必须分开：值、地址、地址中的内容

假设：

```cpp
int x = 42;
```

为了演示，假设 `x` 位于 `0x1000`：

```text
x 的值：42
x 的地址：0x1000
地址 0x1000 开始的 4 字节：2A 00 00 00
```

这三个说法不同：

- `x`：读取对象保存的值；
- `&x`：取得对象地址；
- `*p`：把 `p` 中保存的数当作地址，到那个地址读取或写入对象。

### 4.3 第一根指针逐句执行

```cpp
int x = 42;
int *p = &x;
int y = *p;
*p = 99;
```

同一个 `*` 在两个位置扮演不同语法角色：

- 声明 `int *p` 中，它说明正在声明的 `p` 是“指向 `int` 的指针”；
- 表达式 `*p` 中，它表示沿 `p` 保存的地址访问目标对象，也叫解引用。

同理，表达式 `&x` 是取 `x` 的地址。

逐句理解：

1. `int x = 42;`：创建一个 4 字节左右的整数对象，保存 42；
2. `int *p = &x;`：创建指针变量 `p`，让它保存 `x` 的地址；
3. `int y = *p;`：读取 `p` 指向的 `int`，复制给 `y`；
4. `*p = 99;`：沿着 `p` 找到 `x`，把那里的值改成 99。

假设 `x` 在 `0x1000`，`p` 自己在 `0x2000`：

```text
变量 x：位于 0x1000，内容是整数 42
变量 p：位于 0x2000，内容是地址 0x1000

p     的值是 0x1000
&p    是 0x2000
*p    是地址 0x1000 处的 int，也就是 x
```

指针变量自己也占内存，也有自己的地址。64 位进程中普通数据指针通常占 8 字节；它指向的对象可能只有 1、2、4 或 8 字节。**指针大小和目标对象大小是两回事。**

### 4.4 指针类型究竟提供什么

比较：

```cpp
char *pc;
int  *pi;
long long *pq;
```

这些指针本身在常见 x86-64 环境中都是 8 字节。类型主要告诉编译器：

1. 解引用时读写多少字节；
2. `p + 1` 应跨过多少字节；
3. 允许怎样解释和操作目标对象。

例如假设 `pi = 0x1000`：

```text
pi + 1 = 0x1004      // int 通常占 4 字节
pc + 1 = 原地址 + 1  // char 占 1 字节
pq + 1 = 原地址 + 8  // long long 通常占 8 字节
```

CPU 并不知道 `int*` 这个源码类型。编译器把“乘以 4”编码进寻址方式，逆向者再从这个步长推测元素类型。

### 4.5 数组、下标与指针算术

```cpp
int a[4] = {10, 20, 30, 40};
```

数组元素连续存放。若 `a[0]` 地址为 `0x1000`：

| 元素 | 地址 | 值 |
|---|---:|---:|
| `a[0]` | `0x1000` | 10 |
| `a[1]` | `0x1004` | 20 |
| `a[2]` | `0x1008` | 30 |
| `a[3]` | `0x100C` | 40 |

对元素访问而言：

```cpp
a[i] == *(a + i)
```

这里的 `+ i` 不是简单增加 i 个字节，而是增加 `i * sizeof(int)` 个字节。

多数表达式中，数组名会转换为指向首元素的指针，但数组和指针并非同一种对象：

```cpp
sizeof(a)   // 整个数组的字节数，本例通常是 16
sizeof(&a[0]) // 一个指针的大小，本例通常是 8
```

指针加减和比较在 C/C++ 语言层只对同一数组对象及其“尾后位置”有明确规则。可以形成 `a + 4` 指向本例数组末尾之后的位置用于比较，但不能解引用它。

再看一个容易混淆的细节：

```cpp
a       // 多数表达式中转换为 int*，指向 a[0]
&a      // 类型是“指向整个 int[4] 数组的指针”
```

两者数值表示常相同，但 `a + 1` 通常前进 4 字节，`&a + 1` 则跨过整个 16 字节数组。这一区别在函数参数和反编译类型推断中很重要。

### 4.6 字符串就是带结束标记的字符序列

C 风格字符串：

```cpp
char s[] = "cat";
```

实际需要 4 字节：

```text
地址递增：  'c'   'a'   't'   '\0'
十六进制：  63    61    74     00
```

`strlen(s)` 数到第一个 `\0`，结果为 3；`sizeof(s)` 在当前作用域中是整个数组大小 4。若字符串缺少可达的 `\0`，还用 C 字符串函数继续读取，就可能越界。

下面两种声明也不同：

```cpp
char writable[] = "cat";       // 创建可写数组，内容是 c a t \0
const char *view = "cat";      // 指向字符串字面量，只通过只读接口观察
```

不要通过去掉 `const` 的指针修改字符串字面量；在 C++ 中这不构成合法写入。

逆向中常见：

```asm
cmp byte ptr [rax], 0
je  end_of_string
```

它常表示检查当前字符是否为字符串终止字节。

> **`validator` 主线进度：** 最终检查函数接收 `const char *input`。`input[i]` 就是 `*(input + i)`，按 1 字节读取；`strlen(input)` 沿地址递增寻找第一个 `\0`。到这里，你已经能解释“输入地址、当前字符、字符串长度”三者的区别。

### 4.7 多级指针

```cpp
int x = 7;
int *p = &x;
int **pp = &p;
```

关系是：

```text
pp ──指向──> p ──指向──> x ──保存──> 7
```

- `pp`：`p` 的地址；
- `*pp`：`p`，其值是 `x` 的地址；
- `**pp`：`x` 的值。

汇编里往往体现为连续两次内存读取：

```asm
mov rax, [rdi]      ; 第一次解引用，取出一个地址
mov eax, [rax]      ; 第二次解引用，取出该地址处的 int
```

注意第二条写的是 `eax`，表示只读 4 字节；目的寄存器仍能完整清零高位。

### 4.8 指针传参为什么能修改外部变量

```cpp
void set_zero(int *p) {
    *p = 0;
}

int main() {
    int x = 123;
    set_zero(&x);
}
```

调用者把 `x` 的地址交给函数。函数不需要知道变量名 `x`，只要沿地址写入 4 字节：

```asm
; Linux System V：第一个整数/指针参数在 rdi
set_zero:
    mov dword ptr [rdi], 0
    ret
```

这里：

- `rdi` 保存地址；
- `[rdi]` 表示地址指向的内存；
- `dword ptr` 明确写 4 字节；
- `rdi` 本身没有被改成 0。

### 4.9 动态分配、生命周期与悬空指针

```cpp
int *p = new int(42);
delete p;
p = nullptr;
```

`new` 从动态存储中取得一块适当空间并构造对象，返回地址；`delete` 结束对象生命周期并释放对应存储。释放后原地址数值可能还留在寄存器或变量里，但它已不再是可用对象的合法访问依据。

逆向里，动态分配通常表现为对 `malloc/free`、`operator new/operator delete` 或封装函数的调用。所谓“堆”不是 CPU 的特殊指令区域，而是运行库分配器管理的一批内存。

### 4.10 初学者最常见的指针错误

```cpp
int *p;            // 未初始化，里面是不可依赖的地址
*p = 1;            // 错误：向未知位置写

int *q = nullptr;
*q = 1;            // 错误：空指针解引用

int a[3];
a[3] = 7;          // 错误：越过数组末尾

int *r = new int(5);
delete r;
int y = *r;        // 错误：释放后使用
```

还要注意声明：

```cpp
int *p, q;         // 只有 p 是指针，q 是 int
```

逆向时，这些错误可能表现为崩溃、数据破坏或漏洞。调试器报错地址附近的最后一次解引用通常是重要线索，但“崩溃处”未必就是最早写坏数据的位置。

### 4.11 函数指针

函数地址也可以被保存并间接调用：

```cpp
int add(int a, int b) {
    return a + b;
}

int (*operation)(int, int) = add;
int result = operation(2, 3);
```

声明 `int (*operation)(int, int)` 可读作：`operation` 是指针，指向“接收两个 `int`、返回 `int`”的函数。括号不能随便省略。

汇编中直接调用和间接调用可能分别像：

```asm
call add             ; 直接调用
call rax             ; 目标地址运行时来自 rax
call qword ptr [rbx] ; 先从内存取函数地址，再调用
```

函数指针常见于回调、状态机、导入表和 C++ 虚派发。逆向时要继续追踪目标地址的来源和可选集合。

### 4.12 `const` 指针的读法

从变量名向外读：

```cpp
int x = 0;
const int *p = &x;          // 可以改 p 指向哪里；不能通过 p 修改目标 int
int *const p2 = &x;         // p2 自己不能改指向；可以修改目标 int
const int *const p3 = &x;   // 两边都受限
```

这些限制主要由编译器在源码层检查，机器码里通常不会给“const”加特殊标签。逆向时要通过写入行为判断某块数据实际上是否被修改。

### 4.13 本章检查点

假设 `int a[3] = {5, 6, 7};`，`a[0]` 位于 `0x2000`，普通 `int` 为 4 字节：

1. `&a[2]` 是多少？
2. `int *p = &a[1]` 后，`p` 的值和 `*p` 的值分别是什么？
3. 汇编中寄存器 `rax = 0x2000` 时，`rax` 和 `[rax]` 有何区别？

答案：`0x2008`；`p` 是 `0x2004`、`*p` 是 6；`rax` 是地址数值，`[rax]` 是该地址处的内存内容，读取宽度还需由指令指定。

## 5. 内存操作数与 x86-64 寻址

### 5.1 方括号形成有效地址；是否访问内存由指令决定

在本文采用的 Intel 语法里，`[rbx]` 写出了以 `rbx` 为有效地址的操作数。对 `mov` 等普通数据指令，它表示访问该地址的内存；对 `lea`，同样的方括号只提供地址计算式，并不读写内存。因此必须把“指令 + 操作数”一起读，不能只凭是否出现 `[]` 判断发生了内存访问：

```asm
mov rax, rbx        ; 复制 rbx 中的数值到 rax
mov rax, [rbx]      ; 把 rbx 当地址，从该地址读取 8 字节到 rax
mov [rbx], rax      ; 把 rax 的 8 字节写到 rbx 指向的位置
lea rax, [rbx]      ; 计算地址 rbx，放入 rax；不读取该地址的内存
```

对普通访存指令，是否有 `[]` 是质的区别：

```text
rbx      → 地址这个数本身
[rbx]    → 去这个地址访问内存
```

### 5.2 访问宽度从哪里看

若寄存器已经说明宽度：

```asm
mov al,  [rbx]      ; 读 1 字节
mov ax,  [rbx]      ; 读 2 字节
mov eax, [rbx]      ; 读 4 字节
mov rax, [rbx]      ; 读 8 字节
```

若另一侧是立即数，汇编器需要显式大小：

```asm
mov byte ptr  [rbx], 1   ; 写 1 字节
mov word ptr  [rbx], 1   ; 写 2 字节
mov dword ptr [rbx], 1   ; 写 4 字节
mov qword ptr [rbx], 1   ; 写 8 字节
```

`ptr` 不是“指针变量”的意思，而是 Intel 汇编用来说明内存操作数宽度的语法。

### 5.3 通用有效地址公式

x86-64 常见内存操作数可以写成：

```text
[base + index * scale + displacement]
```

- `base`：基址寄存器；
- `index`：索引寄存器；
- `scale`：只能是 1、2、4、8；
- `displacement`：常量偏移，可正可负。

例如：

```asm
mov eax, [rdi + rcx*4 + 8]
```

假设 `rdi = 0x1000`、`rcx = 3`，则有效地址为：

```text
0x1000 + 3*4 + 8 = 0x1014
```

然后从 `0x1014` 读取 4 字节到 `eax`。这很像：

```cpp
int value = *(int *)((char *)base + index * 4 + 8);
```

更常见的语义要结合类型恢复为数组或字段访问，而不是保留难读的强制转换。

### 5.4 数组访问为什么常带 scale

```cpp
int get(const int *a, long i) {
    return a[i];
}
```

System V 下 `a` 在 `rdi`，`i` 在 `rsi`，典型核心指令：

```asm
mov eax, dword ptr [rdi + rsi*4]
ret
```

`*4` 是 `sizeof(int)`。若看到 `*8`，候选可能是 8 字节整数、指针数组或 `double`；这只是线索，仍需结合使用方式验证。

> **`validator` 主线进度：** 字节数组不需要缩放。若 `rdi` 是输入基址、`rcx` 是索引 i，`movzx eax, byte ptr [rdi + rcx]` 就是读取并零扩展 `input[i]`；key 和 target 也会使用相同的“基址 + i”。

### 5.5 字段访问为什么常是固定偏移

```cpp
struct Point {
    int x;
    int y;
};

int sum(const Point *p) {
    return p->x + p->y;
}
```

一种典型汇编：

```asm
mov eax, dword ptr [rdi]       ; p->x，偏移 0
add eax, dword ptr [rdi + 4]   ; p->y，偏移 4
ret
```

所以“同一基址附近反复出现固定偏移”常是结构体或对象字段的证据。

### 5.6 `lea`：只算地址，不访问内存

```asm
lea rax, [rdi + rsi*4 + 8]
```

它只计算 `rdi + rsi*4 + 8` 并写入 `rax`，不会读取结果地址中的内容。常见用途有两类：

```cpp
// 1. 取地址
int *p = &a[i];

// 2. 利用寻址硬件做普通整数计算
long y = x * 5 + 3;
```

第二类可能变成：

```asm
lea rax, [rdi + rdi*4 + 3]   ; rax = 5*rdi + 3
```

所以 `lea` 不能机械翻译成 C++ 的 `&`。判断标准是结果之后是否被当作地址解引用、传给需要指针的函数，还是继续参加普通算术。

### 5.7 RIP 相对寻址

位置无关代码常用：

```asm
lea rdi, [rip + message]           ; 取得 message 地址
mov eax, dword ptr [rip + counter] ; 读取全局 counter
```

其中有效地址以“下一条指令附近的 RIP”加相对位移计算。反汇编器通常已帮你标成符号名。区分：

```asm
lea rax, [rip + object]   ; rax = &object
mov eax, [rip + object]   ; eax = object 的 4 字节值
```

### 5.8 本章检查点

假设 `rbx = 0x3000`、`rcx = 2`：

1. `[rbx + rcx*8 + 0x10]` 的有效地址是多少？
2. `lea rax, [rbx + 4]` 会不会读取 `0x3004` 的内容？
3. `movzx eax, byte ptr [rbx]` 读取几字节？

答案：`0x3020`；不会，只计算地址；1 字节，随后零扩展到 32 位。

## 6. 数据传送、扩展与算术指令

这不是完整指令手册，只讲逆向初期最常见且能组成大多数逻辑的部分。

### 6.1 `mov` 及其限制

直接编码在指令里的常量叫立即数，例如下面的 `123`。

```asm
mov rax, rbx           ; 寄存器 → 寄存器
mov rax, 123           ; 立即数 → 寄存器
mov rax, [rbx]         ; 内存 → 寄存器
mov [rbx], rax         ; 寄存器 → 内存
```

普通 `mov` 通常不允许源和目的同时都是一般内存操作数：

```asm
; mov [rax], [rbx]     ; 一般不成立
mov rcx, [rbx]
mov [rax], rcx         ; 通过寄存器中转
```

而且两侧宽度通常要一致。把 1 字节读进 8 字节寄存器时，需要说明怎样填充剩余位。

### 6.2 零扩展与符号扩展

零扩展适合把无符号小整数变宽：

```asm
movzx eax, byte ptr [rdi]   ; 8 → 32，高位补 0
```

若内存字节是 `0xFF`，结果 `eax = 255`。

符号扩展适合把有符号小整数变宽：

```asm
movsx eax, byte ptr [rdi]   ; 8 → 32，复制符号位
```

若内存字节是 `0xFF`，结果 `eax = 0xFFFFFFFF`，按 32 位有符号数解释为 `-1`。

常见变体：

```asm
movzx eax, al               ; 8 → 32 零扩展
movsx eax, ax               ; 16 → 32 符号扩展
movsxd rax, eax             ; 32 → 64 符号扩展
```

`mov eax, eax` 这类 32 位写入会让完整 `rax` 零扩展；但若要把负的 32 位 `int` 变成负的 64 位整数，必须使用符号扩展语义。

### 6.3 加减乘与取负

```asm
add eax, ecx        ; eax += ecx
sub eax, 5          ; eax -= 5
inc eax             ; eax += 1
dec eax             ; eax -= 1
neg eax             ; eax = -eax
imul eax, ecx       ; 低 32 位有符号乘法结果放 eax
imul eax, ecx, 10   ; eax = ecx * 10
```

乘法低位结果在位级上常对有符号、无符号都可用；当程序需要完整双倍宽度结果或检查溢出时，`mul`/`imul` 的区别才更直接显现。

### 6.4 除法为什么显得特殊（第二遍选读）

记号 `RDX:RAX` 表示把两个 64 位寄存器拼成一个 128 位被除数：`RDX` 是高 64 位，`RAX` 是低 64 位。

64 位无符号除法：

```asm
xor edx, edx        ; RDX = 0，准备高 64 位
mov rax, rdi        ; 假设 rdi 保存 64 位被除数
div rcx             ; RDX:RAX ÷ RCX
                    ; 商在 RAX，余数在 RDX
```

64 位有符号除法：

```asm
mov rax, rdi        ; 假设 rdi 保存 64 位被除数
cqo                 ; 把 RAX 的符号扩展到 RDX:RAX
idiv rcx            ; 有符号除法；商 RAX，余数 RDX
```

对应 32 位常见 `cdq` + `idiv r/m32`，其中 `r/m32` 是手册对“32 位寄存器或 32 位内存操作数”的缩写；商在 `eax`，余数在 `edx`。看到 `cqo/cdq` 后紧跟 `idiv`，通常就是为有符号除法准备被除数。

除数为常量时，优化器可能改成乘某个“魔数”再移位。不要因为没看到 `div` 就断言源码没有除法。

### 6.5 位运算

```asm
and eax, 0xFF       ; eax &= 0xFF，只保留低 8 位
or  eax, 1          ; eax |= 1，把最低位置 1
xor eax, ecx        ; eax ^= ecx
not eax             ; eax = ~eax
shl eax, 3          ; 逻辑左移 3 位
shr eax, 3          ; 逻辑右移，高位补 0
sar eax, 3          ; 算术右移，复制符号位
rol eax, 5          ; 循环左移
ror eax, 5          ; 循环右移
```

常见模式：

| 汇编 | 常见意图 |
|---|---|
| `and eax, 1` | 取奇偶位 |
| `and eax, 0xFF` | 截成一个字节 |
| `xor eax, eax` | 清零 |
| `xor byte ptr [...], key` | 简单异或变换 |
| `shl eax, 4` | 乘 16，或腾出低 4 位 |
| `shr eax, 8` | 取更高字节/无符号除以 256 |
| `rol/ror` | 位混淆、哈希或某些密码算法组成部分 |

单个特征不是算法证明。比如出现 `xor` 不等于“这一定是异或加密”；编译器也用它清零或组合普通逻辑。

## 7. RFLAGS、比较与条件跳转

### 7.1 `cmp` 不保存减法结果

```asm
cmp eax, ecx
```

它在内部按 `eax - ecx` 更新相关标志，但不把差写回 `eax`。随后条件跳转读取标志：

```asm
cmp eax, ecx
je  equal_path
```

`je`/`jz` 检查零标志 `ZF`，所以相等时跳转。

### 7.2 四个最重要的标志

| 标志 | 含义 | 直观用途 |
|---|---|---|
| `ZF` | Zero Flag | 结果是否为 0 |
| `CF` | Carry Flag | 无符号进位/借位 |
| `SF` | Sign Flag | 结果最高位是否为 1 |
| `OF` | Overflow Flag | 有符号结果是否超出表示范围 |

`CF` 主要服务无符号关系；`SF` 与 `OF` 的组合服务有符号关系。相同位模式采用不同跳转，就会得到不同判断。

### 7.3 有符号与无符号跳转必须分开

在 `cmp a, b` 后：

| 关系 | 有符号跳转 | 无符号跳转 |
|---|---|---|
| `a == b` | `je` / `jz` | 同左 |
| `a != b` | `jne` / `jnz` | 同左 |
| `a > b` | `jg` | `ja` |
| `a >= b` | `jge` | `jae` |
| `a < b` | `jl` | `jb` |
| `a <= b` | `jle` | `jbe` |

字母可辅助记忆：

- `g/l`：greater/less，表示有符号；
- `a/b`：above/below，表示无符号。

例如 32 位 `eax = 0xFFFFFFFF`，`ecx = 1`：

- 有符号看：`-1 < 1`，所以 `jl` 成立；
- 无符号看：`4294967295 > 1`，所以 `ja` 成立。

### 7.4 `test` 常用于检查零、位和空指针

```asm
test rdi, rdi       ; 计算 rdi & rdi，只更新标志
je   is_null        ; rdi == 0 时跳
```

这等价于检查 `rdi` 是否为零，并不会改动 `rdi`。

```asm
test eax, 1
jne  is_odd
```

检查最低位是否为 1，常对应奇数判断。

### 7.5 `setcc` 把条件变成 0 或 1

```cpp
int is_greater(int a, int b) {
    return a > b;
}
```

可能变成：

```asm
xor eax, eax        ; 先确保完整返回值为 0
cmp edi, esi
setg al             ; 若有符号 edi > esi，则 al = 1，否则 al = 0
ret
```

`sete/setne/setg/seta/...` 与对应条件跳转共享条件，只是把布尔结果写入一个字节，不改变控制流。

> **`validator` 主线进度：** `cmp al, byte ptr [target_base + rcx]` 比较当前变换结果与目标字节，`jne fail` 表示只要有一轮不等就立即失败。这个 `jne` 读取的是 `cmp` 刚刚留下的 `ZF`。

### 7.6 条件移动 `cmovcc`

```asm
cmp   eax, ecx
cmovg eax, edx      ; 若有符号 eax > ecx，则用 edx 替换 eax 的低 32 位
```

`cmovcc` 可让某些 `if` 不产生跳转，所以逆向控制流不能只寻找 `jcc`。还要追踪操作数宽度：条件为假时，`eax` 的低 32 位不被替换，但 32 位目标形式仍会把 `rax` 高 32 位清零。若源是内存，CPU 还可能在条件为假时访问该内存并报告异常；`cmov` 不是“条件为假就完全不碰源操作数”。

### 7.7 不要越过会改标志的指令找比较

```asm
cmp eax, ecx
add edx, 1          ; add 也会修改标志
je  somewhere       ; 这里读取的是 add 留下的标志，不再是 cmp 的
```

分析 `jcc/setcc/cmovcc` 时，向上寻找最近一次真正定义相关标志的指令，而不是默认对应最近的 `cmp` 文本。

### 7.8 本章检查点

1. `cmp eax, 10` 后 `jl target` 表示哪种比较？
2. `test rax, rax` 后 `jne target` 常表示什么？
3. 为什么 `cmp eax, ecx` 不会破坏 `eax`？

答案：把 `eax` 按有符号 32 位数与 10 比较，小于则跳；`rax != 0`；`cmp` 只按减法结果更新标志，不保存差值。

## 8. 从跳转恢复 `if`、循环与 `switch`

### 8.1 基本块和控制流图

**基本块**是一段从入口顺序执行到末尾、内部没有分叉的指令。块末通常是：

- 条件跳转；
- 无条件 `jmp`；
- `call` 后继续；
- `ret`；
- 间接跳转。

函数不是一条长直线，而是一张控制流图（CFG）。先给块编号并画箭头，常比逐行翻译更快理解整体。

### 8.2 `if / else`

```cpp
int abs_like(int x) {
    if (x < 0)
        return -x;
    return x;
}
```

一种直接汇编：

```asm
mov eax, edi
test edi, edi
jge non_negative
neg eax
non_negative:
ret
```

读法：先假设返回 `x`；若 `x >= 0` 跳过取负，否则执行 `neg`。注意源码条件是 `x < 0`，汇编却可能使用其反条件 `x >= 0` 跳过分支。

边界提醒：若 `x == INT_MIN`，C/C++ 的 `-x` 发生有符号溢出而没有定义结果；`neg eax` 的机器行为则是保留 `0x80000000` 并设置溢出标志。这里的源码映射只讨论 C/C++ 语义有定义的输入。

优化器也可能写成无跳转序列或 `cmov`，所以恢复的是语义，不是括号形状。

### 8.3 `while` 循环

```cpp
int sum_to(int n) {
    int s = 0;
    int i = 1;
    while (i <= n) {
        s += i;
        ++i;
    }
    return s;
}
```

未优化风格的核心结构：

```asm
xor eax, eax        ; s = 0
mov ecx, 1          ; i = 1
check:
cmp ecx, edi
jg  done            ; i > n 时退出（有符号）
add eax, ecx        ; s += i
inc ecx             ; ++i
jmp check
done:
ret
```

识别循环的关键是**回边**：某条跳转回到较早地址。找出：初始化、循环条件、循环体、更新、出口。

> **`validator` 主线进度：** 把 i 放在 `rcx`，从 0 开始，每轮读取 `input[i]`、变换并比较，随后 `inc rcx; cmp rcx, 6; jb loop`。这就是第 16 章六字节验证器的循环骨架。

### 8.4 `for` 只是组织形式

```cpp
for (int i = 0; i < n; ++i) {
    body(i);
}
```

机器层没有专门的 `for` 指令。它通常仍是初始化 + 比较 + 条件跳转 + 循环体 + 更新 + 回跳。反编译器选择显示 `for` 或 `while` 只是可读性决策。

### 8.5 `do / while`

如果先执行循环体、末尾再检查并向上跳，可能对应至少执行一次的 `do / while`：

```asm
loop_body:
    ; ...
    dec ecx
    jne loop_body
```

但也可能是优化后的其他循环。仍要依据入口和退出边确认。

### 8.6 短路逻辑

```cpp
if (p != nullptr && *p == 7) { ... }
```

典型控制流先判空，再解引用：

```asm
test rdi, rdi
je   false_path
cmp  dword ptr [rdi], 7
jne  false_path
; true_path
```

两个条件之间的跳转可能就是 C/C++ 的 `&&` 或 `||` 短路语义。不要急着把每个跳转都恢复成独立 `if`。

### 8.7 `switch` 与跳转表（第二遍选读）

分支少时，`switch` 可能只是连续比较；分支密集时可能使用跳转表：

```asm
cmp edi, 5
ja  default_case              ; 无符号范围检查，也同时排除负数
mov edi, edi                  ; 把已验证的 32 位索引零扩展到完整 rdi
lea rax, [rip + jump_table]
movsxd rdx, dword ptr [rax + rdi*4]
add rax, rdx
jmp rax
```

分析步骤：

1. 找到进入表之前的范围检查；
2. 确认索引是否先减去最小 case；
3. 判断表项是绝对地址还是相对偏移；
4. 枚举每个合法索引对应的目标基本块；
5. 注意多个 case 可能共用同一目标。

这里 `ja` 的无符号比较很巧：负数按无符号解释为很大的数，也会进入默认分支。

## 9. 栈、`call` 与 `ret`

### 9.1 栈首先是一段普通内存

栈不是另一种神秘存储器。它是进程地址空间中的一段内存，`rsp` 保存当前栈顶地址。常见 x86-64 代码中，栈向更小地址增长：

```text
较高地址
0x...1200  调用者较早的数据
0x...11F8  某个栈槽
0x...11F0  ← rsp（当前栈顶）
0x...11E8  尚未占用
较低地址
```

“向下增长”指数字地址变小，不是屏幕上的固定方向。

### 9.2 `push` 与 `pop`

对常见 64 位寄存器操作，可近似理解：

```asm
push rax
; rsp = rsp - 8
; [rsp] = rax

pop rbx
; rbx = [rsp]
; rsp = rsp + 8
```

后进先出只是这种地址更新规则的结果。

### 9.3 `call` 与 `ret` 的本质

```asm
call function
```

做两件关键事：

1. 把 `call` 后下一条指令的地址压栈，称为返回地址；
2. 把执行位置改到 `function`。

```asm
ret
```

从 `[rsp]` 取出返回地址给 `rip`，并让 `rsp += 8`。所以函数知道执行 `ret` 后回到哪里，不是因为记住了调用者名字，而是因为返回地址在栈上。

### 9.4 为什么函数需要栈帧

函数可能需要保存：

- 返回地址；
- 必须保护的寄存器旧值；
- 放不进寄存器或必须有地址的局部变量；
- 传给其他函数的栈参数；
- 对齐填充和临时空间。

一种典型的未优化函数开头：

```asm
push rbp
mov rbp, rsp
sub rsp, 0x20
```

结尾：

```asm
mov rsp, rbp
pop rbp
ret
```

或用：

```asm
leave       ; 近似 mov rsp, rbp; pop rbp
ret
```

这建立了栈帧，但**不是所有函数都有 `rbp` 栈帧**。优化器常省略 `rbp`，直接以 `rsp` 访问栈槽；叶函数甚至可能完全不用栈。

### 9.5 栈帧图要按具体指令画

执行：

```asm
push rbp
mov rbp, rsp
sub rsp, 0x20
```

后，一种示意：

```text
高地址
[rbp + 8]   返回地址
[rbp]       调用者的旧 rbp
[rbp - 4]   可能的 4 字节局部变量
...
[rbp - 0x20]  ← 当前 rsp 附近
低地址
```

偏移含义不是固定法律。只要中途有 `push`、额外 `sub rsp`、动态对齐或不同优化，布局就会变化。以当前函数实际的 `rsp/rbp` 修改过程为准。

### 9.6 局部数组与越界的机器视角

```cpp
char buf[16];
```

可能位于 `[rbp-0x20]` 开始的一段栈空间。若程序向后写超过 16 字节，可能覆盖相邻局部变量、保存的寄存器乃至控制数据。逆向时需要同时记录：

- 缓冲区起点；
- 允许长度；
- 写入指令或库函数实际长度；
- 相邻栈槽是什么。

不要因为反编译器把变量显示成 `char buf[16]` 就忽略真实偏移；变量边界也是反编译器推断的一部分。

### 9.7 栈对齐

现代 ABI 对调用边界有对齐要求，尤其因为 SIMD 指令和被调函数约定。System V AMD64 中，调用者通常在执行 `call` 前让 `rsp` 处于 16 字节对齐状态；`call` 又压入 8 字节返回地址，所以被调函数刚入口时常见 `rsp % 16 == 8`。

这解释了看似“多减了 8 字节”的栈空间。不要把所有 `sub rsp, N` 都解释成局部变量总大小，其中可能包含对齐填充。

### 9.8 本章检查点

1. 假设 `rsp = 0x1000`，执行 `push rax` 后 `rsp` 是多少？
2. `call` 压入的是什么？
3. 为什么不能看到 `[rbp-8]` 就武断说它一定是某一种变量？

答案：`0x0FF8`；下一条指令的返回地址；栈布局取决于实际序言、保存动作、对齐和优化，偏移本身不携带源码类型。

## 10. 函数调用约定：不同函数怎样合作

CPU 的 `call` 只负责返回地址和控制转移，并不知道“第一个参数”是什么。参数放哪里、谁保护寄存器、栈怎样对齐，属于 **ABI（应用二进制接口）约定**。

逆向时请把结论分层：

- **[ISA 事实]**：`call` 压入返回地址，写 `eax` 清 `rax` 高 32 位；
- **[ABI 约定]**：System V 第一个整数/指针参数在 `rdi`；
- **[编译器常见形态]**：某个优化器喜欢用 `lea` 完成乘 5；
- **[逆向假设]**：`[rbx+0x18]` 可能是对象字段。

前两类有明确规格；后两类需要上下文和动态证据。不要把“常见形态”背成 CPU 规则。

### 10.1 System V AMD64：Linux 主线规则

对普通整数和指针参数，前六个依次放：

| 参数序号 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 寄存器 | `rdi` | `rsi` | `rdx` | `rcx` | `r8` | `r9` |

现在回看第 2 章的运算，把它放进真正函数：

```cpp
int add_then_double(int a, int b) {
    return (a + b) * 2;
}
```

一种可能的优化后形态：

```asm
; System V：edi = a，esi = b
mov eax, edi
add eax, esi
add eax, eax
ret                 ; 32 位整数返回值在 eax
```

到这里，`edi/esi` 的来源和 `ret` 的作用都已经有了前置知识，不需要把 ABI 当成寄存器的固有属性。

常见返回规则：

- 整数、指针：`rax`；
- 较小的 32 位整数返回值常写 `eax`；
- 浮点返回值通常在 `xmm0`；XMM 是一组用于浮点和向量数据的寄存器；
- 大型结构体返回可能由调用者传入隐藏指针，不能一概看成 `rax` 装完整对象。

浮点参数使用 XMM 寄存器并有独立分类规则；复杂结构体还涉及 ABI 分类。入门阶段先把“六个整数/指针参数”练熟，遇到混合参数再查 ABI 或用调试器验证。

### 10.2 caller-saved 与 callee-saved

如果调用者希望某个临时值在调用后还存在，双方必须知道谁负责保存。

System V 常见分类：

| 类别 | 寄存器 | 直观含义 |
|---|---|---|
| 返回值/易失 | `rax` | 被调函数可改 |
| 参数/易失 | `rdi rsi rdx rcx r8 r9` | 被调函数可改 |
| 其他易失 | `r10 r11` | 被调函数可改 |
| 非易失 | `rbx rbp r12 r13 r14 r15` | 被调函数若使用，返回前须恢复 |
| 栈指针 | `rsp` | 返回调用者时必须恢复到约定位置 |

“caller-saved”不是每次都必须保存，而是调用者只有在还需要旧值时才保存。“callee-saved”也不是函数必须全部压栈，而是只需保护自己实际改动的那些。

例如函数把一个指针跨 `strlen` 调用保存到 `rbx`：

```asm
push rbx            ; 先保存调用者的 rbx
mov  rbx, rdi       ; rbx 保存当前函数要长期使用的指针
call strlen
; 此处 rdi 可能已被 strlen 改动，但 rbx 仍应保持
; ...
pop  rbx
ret
```

> **`validator` 主线进度：** `check(input)` 进入时 `input` 在 `rdi`。因为 `strlen` 可以改动易失寄存器，函数先把地址复制到非易失的 `rbx`，并在使用 `rbx` 前后保存/恢复它；这正是后面完整汇编序言的由来。

### 10.3 第七个及更多参数（第二遍选读）

超出寄存器容量的参数会按 ABI 规则放到栈上传递，但不要背“从右到左逐个 push”。编译器常先一次分配栈空间，再写入对应槽位；结构体和浮点参数还有分类规则。

分析调用点时：

1. 从 `call` 向前追踪参数寄存器的最后定义；
2. 查看调用前写入的栈槽；
3. 确认中间是否有指令覆盖寄存器；
4. 结合被调函数如何读取参数反向验证。

### 10.4 System V 的 red zone（第二遍选读）

System V AMD64 允许用户态函数使用当前 `rsp` 以下 128 字节的 **red zone** 作为临时空间，前提是函数在使用期间的约定条件满足。不再调用其他函数的函数叫叶函数；它可能因此访问 `[rsp-...]` 而不先执行 `sub rsp, ...`。

Windows x64 没有同样规则。内核代码、异常环境或特殊编译选项也可能不同，所以这是 ABI 特性，不是 x86-64 指令集特性。

### 10.5 `[第二遍阅读 / Windows 支线]` Microsoft x64 对照

Windows x64 的前四个整数/指针参数是：

| 参数序号 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 寄存器 | `rcx` | `rdx` | `r8` | `r9` |

关键差异：

- 调用者为被调函数预留 32 字节 **shadow space（影子空间）**；
- 整数/指针返回值通常在 `rax`；
- `rbx rbp rdi rsi r12-r15` 为常见非易失整数寄存器；
- `xmm6-xmm15` 也是非易失的一部分，而 `xmm0-xmm5` 易失；
- 调用边界同样要求合适的 16 字节对齐，但具体入口和序言要按 Microsoft ABI 分析；
- 不使用 System V red zone。

典型调用点可能出现：

```asm
sub rsp, 0x28       ; 32 字节影子空间 + 对齐需要
mov ecx, 10         ; 第一个 int 参数
mov edx, 20         ; 第二个 int 参数
call target
add rsp, 0x28
```

看到 `rdi/rsi` 或 `rcx/rdx` 只能提供 ABI 线索，最终还要结合文件格式（ELF/PE）、导入、编译器特征和函数实际行为。

### 10.6 间接调用与函数指针

```asm
call rax
```

目标地址就是 `rax` 当前保存的数值。

```asm
call qword ptr [rax]
```

则先从 `rax` 指向的内存读取 8 字节，把读出的值当目标地址，多了一次解引用。它们可能对应：

- 普通函数指针；
- 回调表；
- 导入表间接调用；
- C++ 虚函数；
- 手写调度器。

看到间接调用先追踪“目标地址来自哪里”，不要直接贴上虚函数标签。

## 11. C 语言结构在汇编中的形状

### 11.1 局部变量不等于栈槽

```cpp
int f(int x) {
    int y = x + 3;
    return y * 2;
}
```

在 `-O0` 下，参数和 `y` 可能被反复写入 `[rbp-...]`；在 `-O2` 下，可能只有：

```asm
lea eax, [rdi + rdi + 6]
ret
```

`y` 完全不存在。逆向时应给“值”命名，而不是假设每个源码变量都必须对应一个固定位置。

### 11.2 类型宽度从访问方式推断

```asm
movzx eax, byte ptr [rdi]        ; 读取 1 字节并零扩展
movsx eax, word ptr [rdi + 2]    ; 读取 2 字节并符号扩展
mov   eax, dword ptr [rdi + 4]   ; 读取 4 字节
mov   rax, qword ptr [rdi + 8]   ; 读取 8 字节
```

这些是当前操作的确凿宽度，却不一定唯一确定原源码类型。1 字节可能是 `char`、`uint8_t`、布尔值、缓冲区字节或结构体的一部分。先记录“事实”，再建立“候选类型”。

### 11.3 结构体对齐与填充

```cpp
struct Record {
    char tag;
    int value;
    short score;
};
```

常见 ABI 下，一种布局是：

```text
偏移 0      tag，1 字节
偏移 1..3   填充
偏移 4..7   value，4 字节
偏移 8..9   score，2 字节
偏移 10..11 尾部填充
总大小 12
```

相应访问可能是：

```asm
movzx eax, byte ptr [rdi]
mov   ecx, dword ptr [rdi + 4]
movsx edx, word ptr [rdi + 8]
```

布局取决于 ABI、对齐属性、打包选项和类特性。逆向恢复结构体时：

1. 汇总同一候选基址的所有固定偏移；
2. 标注每个偏移访问宽度和读/写方向；
3. 查看是否有数组式步长；
4. 检查分配大小和初始化函数；
5. 在多个调用点验证，不要只凭一次 `[rbx+0x18]` 下结论。

### 11.4 结构体数组

若 `sizeof(Record) == 12`，`records[i].value` 的地址大致是：

```text
base + i*12 + 4
```

x86 scale 只能是 1、2、4、8，编译器可能拆成：

```asm
lea rax, [rsi + rsi*2]          ; 3*i
mov eax, [rdi + rax*4 + 4]      ; base + 12*i + 4
```

不要因为寻址中最终 `*4` 就误判元素大小只有 4；要把前面的索引计算一并追踪。

### 11.5 二维数组

```cpp
int a[3][5];
int x = a[i][j];
```

按行连续存放时：

```text
地址 = base + (i*5 + j)*4
```

汇编可能先算 `i*5`，再加 `j`，最后乘 4。恢复维度需要结合已知边界、循环上限、分配大小，单凭一个地址公式可能有多种等价解释。

### 11.6 C 字符串循环

下面函数返回字符串长度，使用 64 位 `size_t` 风格计数：

```asm
; rdi = const char *s
xor eax, eax
loop:
    cmp byte ptr [rdi + rax], 0
    je  done
    inc rax
    jmp loop
done:
    ret
```

关键证据：逐字节访问、与零比较、索引递增。它与 `strlen` 语义相似，但仍可能是扫描某种零结尾字节缓冲区。

### 11.7 `memcmp` 与 `strcmp` 不一样

- `memcmp(a,b,n)` 比较恰好 n 个字节，可包含零字节；
- `strcmp(a,b)` 按 C 字符串比较，遇到 `\0` 结束；
- `strncmp` 最多比较 n 个字符，但仍受终止字节影响。

逆向验证器时要确认长度参数和终止条件。把 `memcmp` 误恢复成字符串比较，可能导致含 `0x00` 的输入约束错误。

### 11.8 全局变量与静态数据

```asm
mov eax, dword ptr [rip + global_count]
lea rdi, [rip + prompt]
```

固定地址附近的数据可能位于只读或可写映射。查看交叉引用和段权限：

- 只被读取、内容像字符串/常量表：候选只读数据；
- 被写入：候选全局状态或动态初始化对象；
- 代码地址数组：候选跳转表或函数指针表。

“位于某个 section”是文件组织证据；运行时真正决定能否执行/读/写的是装载 segment/page 的映射权限。

### 11.9 递归没有专属指令

递归只是函数直接或间接再次 `call` 自己。每一层通常有新的返回地址和所需状态：

```cpp
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

逆向时先找基例分支，再确认递归调用前保存了哪些值、返回后怎样合并。优化器也可能把尾递归改成循环，或对简单函数做更激进变换。

## 12. 从可执行文件到进程地址空间

这一章连接“磁盘上的字节”和“调试器里的地址”。

### 12.1 更准确的构建链

简化但实用的流程：

```text
预处理后的 C/C++
   ↓ 编译器前端与优化/代码生成
汇编文本（可选的中间观察形式）
   ↓ 汇编器
目标文件 .o / .obj（机器码、数据、符号、重定位信息）
   ↓ 链接器
ELF / PE 可执行文件或共享库
   ↓ 操作系统加载器与动态链接器
进程中的代码、数据、栈、堆和共享库映射
```

源码一行不保证对应一条汇编；一条汇编语句也可能是汇编器伪指令。最终 CPU 执行的是机器指令字节。

### 12.2 section 与 segment

在 ELF 中可以先这样区分：

- **section（节）**主要服务链接和文件组织，如 `.text`、`.rodata`、`.data`、`.bss`、符号表；
- **segment（段/程序头描述的装载区域）**主要告诉加载器把哪些文件区域映射到内存并赋予什么权限。

多个 section 可能落在同一个装载 segment 中；运行时内存布局也不是把 section 名简单首尾拼接。逆向文件结构用 section 很方便，讨论进程页权限时优先看 segment/mapping。

常见用途只是线索：

| 名称 | 常见内容 |
|---|---|
| `.text` | 可执行机器码 |
| `.rodata` | 字符串和只读常量 |
| `.data` | 有初值的可写全局/静态数据 |
| `.bss` | 文件中不保存完整初值、装载后置零的数据 |

### 12.3 虚拟地址、文件偏移和 RVA

- **文件偏移**：某字节在磁盘文件中的位置；
- **虚拟地址 VA**：进程运行时访问的位置；
- **RVA**：相对映像基址的偏移，PE 工具中常见。

它们不是同一个数字。把调试器地址换算成文件偏移或静态工具地址，需要装载基址和对应 section/segment 映射信息，不能直接把十六进制地址当文件偏移修改。

### 12.4 PIE、ASLR 与地址变化

ASLR 会随机化合适映像和映射的运行位置；PIE 让主程序也能像位置无关映像一样在不同基址装载。于是：

```text
运行时地址 = 本次装载基址 + 模块内相对偏移
```

静态工具显示的地址、调试器本次地址、另一次运行地址可能不同，但模块内偏移往往仍可对应。RIP 相对寻址是 x86-64 常见模式，非 PIE 程序也会使用；PIE/PIC 只是更依赖位置无关的引用方式。

### 12.5 符号、strip 和名字

符号可以提供函数/全局对象名字和地址信息。`strip` 常移除大量便于调试的符号，但：

- 机器码和程序运行所需数据仍在；
- 动态链接需要的导入相关信息通常仍可观察；
- 字符串、控制流和调用关系仍可分析；
- C++ 动态符号或 RTTI 有时仍泄露有用类型线索。

没有符号时给函数重命名是逆向分析的重要工作，例如 `sub_401230` → `check_length` → `verify_input`，名称应随证据增加而修正。

### 12.6 ELF 的 PLT/GOT 与 PE 的 IAT

入门先掌握概念：外部函数地址可能要到装载或运行时才能最终确定，因此代码通过中间表或跳板调用。

- ELF 常见 PLT/GOT 机制；
- PE 常见导入地址表 IAT；
- 反汇编中可能出现 `strlen@plt` 或 `call qword ptr [rip+...]`；
- 中间跳转不代表程序员手写了额外函数。

具体懒绑定、重定位类型和导入解析可以后学。做基础题时，先利用工具识别最终外部 API 及其参数。

> **`validator` 主线进度：** `key` 和 `target` 在源码中是只读常量，常见构建会把相关信息放进只读映射，并通过 RIP 相对地址取得。优化后它们也可能被合并或折叠，所以“只读区找到两张表”是常见形态，不是必须保持的对象身份。

### 12.7 典型进程映射不是固定图

你会看到代码、只读数据、可写数据、堆、栈、共享库、匿名映射和未映射空洞。它们的地址可能受 ASLR、加载器、运行库和分配行为影响。

因此：

- 不要背某个固定栈地址；
- 访问地址前确认当前进程和当前运行是否映射；
- 用调试器的 memory map 查看权限；
- 地址“很像栈/堆”只是启发式证据。

## 13. C++ 逆向：在 C 模型上增加对象语义

C++ 最终仍执行寄存器、内存和跳转，但编译器需要实现对象、重载、虚派发、异常和模板等语义。下面只建立入门地图。

### 13.1 引用在机器层常像指针，但不是同一源码概念

```cpp
void inc(int &x) {
    ++x;
}
```

在常见实现中，函数需要接收 `x` 的地址：

```asm
add dword ptr [rdi], 1   ; System V 示例
ret
```

但 C++ 引用在语言层有自己的绑定和生命周期规则，优化后也可能完全消失。反编译器可能把同一种机器形态显示成 `int*` 或 `int&`，两者未必能从局部机器码唯一确定。

### 13.2 `this` 是隐含对象参数

```cpp
class Player {
public:
    int hp;
    int getHp() const { return hp; }
};
```

普通非静态成员函数需要知道作用于哪个对象。简单 System V 示例中，`this` 是第一个指针参数，位于 `rdi`：

```asm
mov eax, dword ptr [rdi]   ; 假设 hp 位于偏移 0
ret
```

Windows x64 下第一个参数通常是 `rcx`。静态成员函数没有 `this`。优化器若已知对象和函数，还可能内联，让这次调用消失。

### 13.3 构造函数和析构函数

构造函数常表现为：

- 接收 `this`；
- 写入字段初值；
- 对含虚函数的对象写入 vptr；
- 调用基类和成员对象构造函数。

析构函数则按相应顺序清理成员、基类和资源。一个类可能出现多个构造/析构变体或编译器生成的辅助函数，不要只凭名字数量判断源码写了多少份。

### 13.4 名字修饰

C++ 需要把命名空间、类、重载参数等编码进链接符号：

- GCC/Clang 在许多 ELF 平台使用 Itanium C++ ABI 风格；上文 `const` 成员函数可见类似 `_ZNK6Player5getHpEv` 的名字；
- MSVC 使用另一套修饰规则，名字形态不同；
- 工具的 demangle 功能可恢复可读签名，但恢复的仍是符号编码信息，不是函数体源码。

若二进制已去符号，名字修饰线索可能消失。

### 13.5 简单单继承下的虚函数调用

典型实现会让多态对象含有一个隐藏的表指针候选，常称 vptr（virtual table pointer）；vptr 指向虚函数表 vtable。一个简化的间接调用可能是：

```asm
mov rax, qword ptr [rdi]       ; 候选：从对象开头取 vptr
call qword ptr [rax + 0x10]    ; 候选：调用表中某个槽位
```

这是**常见 ABI 实现模式，不是 C++ 语言保证对象第一个字段必为 vptr**。多继承、虚继承、只做 `this` 调整/跳转的小型桩函数（thunk）、析构槽以及 Itanium/MSVC ABI 差异都会改变布局。普通回调表也能产生相同的“两次解引用 + 间接调用”。

验证虚表假设可看：

1. 该表是否位于只读数据并包含多个代码地址；
2. 构造函数是否把表地址写进对象固定偏移；
3. 多个对象是否共享该表；
4. 间接调用前 `this` 是否按 ABI 放在首参数位置；
5. RTTI、符号或交叉引用是否支持类层次判断。

### 13.6 多继承与 thunk 的最小认识（第二遍选读）

一个对象可能包含多个基类子对象，也可能有多个 vptr。调用某个基类视角的虚函数前，编译器有时通过小型 **thunk** 调整 `this` 再跳到真实实现：

```asm
sub rdi, 0x10
jmp real_method
```

看到“只调整首参数就尾跳”的小函数，不要急着删除，它可能表达重要的对象布局关系。

### 13.7 RTTI、异常和 STL（第二遍选读）

- 运行时类型信息（RTTI）可能留下 typeinfo、类名和继承关系线索；
- 异常处理会引入展开表、异常落地点/清理入口（landing pad）和编译器运行库调用；
- STL 模板会产生长符号、内联和复杂实现细节；
- `std::string`、`std::vector` 的布局取决于实现、版本、ABI 和编译选项。

初学阶段遇到庞大库代码时，先找“你的输入进入哪里、关键比较在哪里、成功分支依赖什么”。把确认是标准库的函数重命名并折叠，不必从第一题就完整逆向 STL 内部。

### 13.8 结构恢复永远是可修正的假设

建议在 IDA/Ghidra 中这样迭代：

```text
第一次：ctx + 0x18，未知 8 字节
更多证据：该值总被解引用，暂命名 data_ptr
调用点证据：指向连续字节并伴随 length 字段
暂定结构：{ ..., uint8_t *data_ptr; size_t length; }
动态验证：检查不同对象实例和边界
```

不要为了让伪代码好看而过早锁死错误类型。正确的类型会同时解释更多访问和调用行为。

### 13.9 C++ 最小可运行实验：观察 `this` 与虚调用

把最终验证器的“长度必须为 6”先包装成一个最小多态类，保存为 `cpp_verifier.cpp`：

```cpp
#include <cstring>

class Verifier {
public:
    virtual bool check(const char *input) const = 0;
    virtual ~Verifier() = default;
};

class SixByteVerifier final : public Verifier {
public:
    bool check(const char *input) const override {
        return std::strlen(input) == 6;
    }
};

__attribute__((noinline))
bool dispatch(const Verifier &verifier, const char *input) {
    return verifier.check(input);
}

int main(int argc, char **argv) {
    SixByteVerifier verifier;
    return argc == 2 && dispatch(verifier, argv[1]) ? 0 : 1;
}
```

```bash
g++ -g -O0 -fno-omit-frame-pointer -fno-pie -no-pie \
    cpp_verifier.cpp -o cpp_verifier
nm -C cpp_verifier | grep -E 'Verifier|dispatch'
objdump -d -Mintel -C cpp_verifier > cpp_verifier.objdump.txt
```

在 `dispatch` 中，System V 下第一个参数槽 `rdi` 保存 `verifier` 的地址，第二个参数 `rsi` 保存输入地址。函数需要从对象取得 vptr，再从表槽间接调用 `check`；调用时 `this` 仍作为目标成员函数的首个隐含参数。用 GDB：

```gdb
break dispatch
run 123456
disassemble /r dispatch
print &verifier
print input
x/gx &verifier
```

你需要提交四项观察：demangle 后的函数名、对象地址、对象开头的候选 vptr、间接调用指令。然后用长度不是 6 的参数再运行，确认退出码从 0 变为 1。这个实验只展示简单单继承 ABI 形态；不要把观察到的具体槽位推广成所有 C++ 实现的永久规则。

## 14. 编译优化与反编译器：源码形状为什么会消失

### 14.1 `-O0` 也不是逐行翻译

无优化构建通常更适合初学，因为它保留更多栈变量和直白控制流。但即使 `-O0`：

- 参数仍要遵守 ABI；
- C++ 前端仍会展开语言语义；
- 临时对象和隐含参数仍可能出现；
- 一行源码仍可对应多条指令；
- 未指定/未定义行为不会获得你期待的保证。

所以 `-O0` 是“更容易观察”，不是“源码与汇编严格一一对应”。

### 14.2 优化器关心等价结果，不关心保留写法

常见优化包括：

- 常量折叠与常量传播；
- 删除无用计算；
- 函数内联；
- 寄存器复用；
- 省略帧指针；
- 循环展开、合并或向量化；
- 公共子表达式消除；
- 尾调用；
- 把分支变成 `cmov/setcc` 或位运算；
- 把常量乘除换成移位、`lea`、乘法和修正序列。

示例：

```cpp
int f(int x) {
    int a = x + 1;
    int b = a * 4;
    return b - 4;
}
```

数学上等于 `4*x`，优化后可能只剩：

```asm
lea eax, [rdi*4]
ret
```

局部变量 `a`、`b` 和源码的运算顺序都消失了。

### 14.3 `sar` 不总等于有符号除以 2 的幂（第二遍选读）

C/C++ 有符号整数除法向 0 截断；`sar` 对负数复制符号位，效果更接近向负无穷舍入。比如 `-1 / 8` 在 C++ 中是 0，而常见算术右移 `-1 >> 3` 得到 -1。

因此编译器实现 `int x / 8` 时可能先对负数加偏置：

```asm
lea eax, [rdi + 7]
test edi, edi
cmovns eax, edi      ; 非负数不用偏置
sar eax, 3
```

这是“一种可能的等价序列”。看到移位时要检查前后的修正，不能只翻译单条指令。

无符号 `x / 8` 则常可直接用：

```asm
mov eax, edi
shr eax, 3
```

### 14.4 常量除法的“魔数”（第二遍选读）

除以 3、7、10 等常量时，编译器可能使用宽乘法、高半结果、移位和符号修正。魔数取决于：

- 位宽；
- 有符号/无符号；
- 取商还是取余；
- 编译器和优化目标。

不要背一个十六进制常量就套全部除法。可把候选序列复制到小程序中，对边界值和随机值验证，或用编译器生成同类型参考代码对比。

### 14.5 内联让函数边界消失

源码调用 `check_char()`，优化后其逻辑可能直接嵌入调用者。相反，编译器也可能生成源码没有写出的辅助函数、thunk 或冷路径函数。

因此：

- “没看到 `call`”不表示源码没调用抽象函数；
- “看到独立函数”也不表示程序员亲手写了它；
- 恢复程序语义应以数据流和控制流为中心。

### 14.6 反编译伪代码是可编辑的假设

反编译器主要猜测：

- 函数边界；
- 参数数量和类型；
- 局部变量划分；
- `if/while/switch` 结构；
- 指针与结构体；
- 有符号性；
- 调用约定。

任何一项猜错都会让伪代码连锁变怪。建议工作顺序：

1. 先核对关键汇编的访问宽度和跳转条件；
2. 修正函数签名和调用约定；
3. 给值和函数重命名；
4. 合并真实属于同一对象的字段；
5. 用动态数据验证；
6. 再把伪代码当作高层视图使用。

### 14.7 未定义行为会反过来影响逆向

例如 C/C++ 中的有符号溢出、越界访问、释放后使用等可能属于未定义行为。编译器在“合法程序不会触发它”的前提下优化，生成结果未必符合你用朴素机器回绕推导的源码直觉。

逆向者需要分清：

- **机器码实际做什么**：当前二进制上的确定事实；
- **某段 C 伪代码是否严格等价**：还要处理位宽、别名、生命周期和未定义行为。

若目标是求出这个二进制接受的输入，以机器码语义为准；若要写可移植复现代码，则必须用明确宽度和已定义操作表达。

## 15. 建立可重复的学习实验

### 15.1 推荐的双工具路线

如果你主要使用 Windows，可以同时准备：

- **Linux/WSL 主线**：GCC 或 Clang、GDB、`objdump/readelf`，练 ELF 和 System V ABI；
- **Windows 对照**：Visual Studio 编译器、x64dbg、IDA/Ghidra，练 PE 和 Microsoft x64 ABI。

不要在同一小例子里来回切换两套 ABI。先完整读懂 Linux 版本，再把同一源码编译为 Windows x64，专门比较参数寄存器、影子空间、导入调用和文件结构。

### 15.2 编译器驱动学习法

准备最小源码 `demo.c`，一次只改变一个概念，然后比较：

```bash
gcc -S -masm=intel -O0 -fno-omit-frame-pointer -fno-pie \
    demo.c -o demo_O0.s
gcc -S -masm=intel -O2 -fno-pie \
    demo.c -o demo_O2.s

gcc -g -O0 -fno-omit-frame-pointer -fno-pie -no-pie \
    demo.c -o demo_O0
gcc -g -O2 -fno-pie -no-pie \
    demo.c -o demo_O2

objdump -d -Mintel demo_O0 > demo_O0.objdump.txt
objdump -d -Mintel demo_O2 > demo_O2.objdump.txt

# 再单独改变 PIE 这一项，避免把地址模式差异误算成优化差异
gcc -g -O2 demo.c -o demo_O2_pie
```

`-fno-pie -no-pie` 只用于最初实验让主程序地址更直观；真实题目可能是 PIE，后面必须学会用模块基址 + 偏移对应地址。

推荐变化序列：

1. `int` 加减；
2. `uint8_t` 与 `int8_t` 扩展；
3. 指针读写；
4. `int`/`char`/`int64_t` 数组下标；
5. `if` 的 signed/unsigned 对比；
6. 循环；
7. 结构体字段和填充；
8. 两层函数调用；
9. 函数指针；
10. 简单 C++ 成员函数和虚函数。

每次先预测，再编译，再解释差异。只看现成答案很难建立直觉。

### 15.3 指针实验：亲眼区分 `p`、`*p` 与 `&p`

保存为 `pointer_lab.c`：

```c
#include <stdint.h>
#include <stdio.h>

__attribute__((noinline))
void pause_here(int *px, int **pp, int *array) {
    (void)px;
    (void)pp;
    (void)array;
    __asm__ volatile("" ::: "memory");
}

int main(void) {
    int x = 0x12345678;
    int a[3] = {10, 20, 30};
    int *p = &a[1];

    pause_here(&x, &p, a);
    printf("x=%x, *p=%d, a[2]=%d\n", x, *p, a[2]);
    return 0;
}
```

`__attribute__((noinline))` 和空的 `__asm__` 是 GCC/Clang 专用的实验支架：前者阻止观察函数被内联，后者为调试器保留一个明确观察点并约束附近内存优化。当前只需原样复制，它们不属于指针知识点。

构建与调试：

```bash
gcc -g -O0 -fno-omit-frame-pointer -fno-pie -no-pie \
    pointer_lab.c -o pointer_lab
gdb ./pointer_lab
```

GDB 中：

```gdb
set disassembly-flavor intel
break *pause_here
run

# System V：rdi=&x，rsi=&p，rdx=&a[0]
info registers rdi rsi rdx rsp rip
p/x $rdi
x/4bx $rdi           # 同一个 x，按 4 个字节看：小端顺序
x/wx $rdi            # 按 4 字节整数看

p/x $rsi
x/gx $rsi            # p 变量自己保存的 8 字节地址
set $tmp = *(void **)$rsi
x/wd $tmp            # 沿 p 解引用，看到 a[1] == 20

x/3wd $rdx           # 连续查看 a 的三个 int
disassemble /s main
```

你应该能说清：

- `rdi` 是 `x` 的地址，不是 `x` 的值；
- `[rsi]` 是变量 `p` 中保存的地址；
- 再沿该地址读 4 字节才得到 20；
- `rdx+8` 指向 `a[2]`；
- 内存按字节显示 `x` 时顺序为何是 `78 56 34 12`。

## 16. 完整逆向实例：从汇编恢复验证器

下面使用一个可手算的小型验证器贯穿静态分析、数据流和求解。汇编是为教学整理的“编译器风格版本”，标签和符号名在 stripped 二进制中可能不存在。

### 16.1 先把目标当黑盒

假设程序行为：

```text
$ ./validator
input: AAAAAA
wrong
```

静态字符串能找到 `wrong`/`correct`，交叉引用把我们带到某个布尔检查函数。根据调用点和 System V ABI，暂时猜测第一个参数 `rdi` 是输入字符串地址。

这里的“字符串指针”仍是假设；下一步看被调函数是否逐字节读取并调用 `strlen` 来验证。

### 16.2 关键数据

反汇编器在只读数据中识别出：

```text
key:     13 37 C0 DE 5A A5
target:  5E 53 BC BE 72 9C
```

### 16.3 检查函数汇编

```asm
; bool check(const char *input) 的一个等价实现
check:
    push rbx
    mov  rbx, rdi                    ; 跨函数调用保存 input
    call strlen                      ; rdi 仍是 input
    cmp  rax, 6
    jne  fail

    xor  ecx, ecx                    ; i = 0
    lea  r8, [rip + key]
    lea  r9, [rip + target]

loop:
    movzx eax, byte ptr [rbx + rcx]  ; eax = input[i]，零扩展
    xor   al, byte ptr [r8 + rcx]    ; 低 8 位 ^= key[i]
    add   al, cl                     ; 低 8 位 += i，按 256 回绕
    cmp   al, byte ptr [r9 + rcx]
    jne   fail

    inc  rcx
    cmp  rcx, 6
    jb   loop                        ; 无符号 i < 6

    mov  eax, 1
    pop  rbx
    ret

fail:
    xor  eax, eax
    pop  rbx
    ret
```

### 16.4 先恢复函数边界和 ABI

证据链：

1. 进入时把 `rdi` 复制到 `rbx`；
2. `rdi` 被传给 `strlen`，支持它是 C 字符串地址；
3. `rbx` 是 System V 非易失寄存器，所以函数先 `push` 保存旧值，返回前 `pop`；
4. `strlen` 返回 `size_t` 到 `rax`，与 6 比较；
5. 函数最终令 `eax` 为 0 或 1，支持布尔返回值假设。

注意：`strlen` 是外部调用，易失寄存器可被改动，所以长期使用的输入地址不能无条件留在 `rdi`。这就是 `rbx` 的意义。

### 16.5 恢复循环

循环状态：

```text
rbx = input 基址
rcx = i
r8  = key 基址
r9  = target 基址
```

每轮地址：

```text
input[i]  → [rbx + rcx]
key[i]    → [r8  + rcx]
target[i] → [r9  + rcx]
```

都按 1 字节访问，因此没有 `*4`。核心关系是：

```text
target[i] = ((input[i] XOR key[i]) + i) mod 256
```

把下面的完整等价实现保存为 `validator.c`，即可复现程序行为：

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

bool check(const char *input) {
    static const uint8_t key[6] = {
        0x13, 0x37, 0xC0, 0xDE, 0x5A, 0xA5
    };
    static const uint8_t target[6] = {
        0x5E, 0x53, 0xBC, 0xBE, 0x72, 0x9C
    };

    if (strlen(input) != 6)
        return false;

    for (size_t i = 0; i < 6; ++i) {
        uint8_t value = (uint8_t)(((uint8_t)input[i] ^ key[i]) + i);
        if (value != target[i])
            return false;
    }
    return true;
}

int main(void) {
    char input[128];

    fputs("input: ", stdout);
    fflush(stdout);

    if (!fgets(input, sizeof input, stdin))
        return 2;

    input[strcspn(input, "\r\n")] = '\0';

    bool ok = check(input);
    puts(ok ? "correct" : "wrong");
    return ok ? 0 : 1;
}
```

构建可调试基线：

```bash
gcc -g -O0 -fno-omit-frame-pointer -fno-pie -no-pie \
    validator.c -o validator
```

这是为了复现实验写出的**等价源码**，不声称是原作者源码。比如原程序也可能手写 `while`，或把数组放在另一结构中，机器语义仍相同。前面的汇编也是为了教学统一整理的等价形态；你本机真实构建的指令与偏移应以 `objdump`/GDB 输出为准。

### 16.6 逆变换求输入

正向关系：

```text
y = ((x XOR k) + i) mod 256
```

逆向时反序操作：

```text
x = ((y - i) mod 256) XOR k
```

Python 求解脚本：

```python
key = bytes([0x13, 0x37, 0xC0, 0xDE, 0x5A, 0xA5])
target = bytes([0x5E, 0x53, 0xBC, 0xBE, 0x72, 0x9C])

answer = bytes(
    (((target[i] - i) & 0xFF) ^ key[i])
    for i in range(6)
)

print(answer)
print(answer.decode())
```

字面输出：

```text
b'Meze42'
Meze42
```

这里 `& 0xFF` 明确表达 8 位回绕。如果改用 Z3 的 8 位 `BitVec`，回绕天然发生；若改用无限精度整数，则必须显式取模。反过来，真实 C 代码中的小整数常先发生整数提升，所以建模位宽必须以具体指令为准，不能看到 `char` 就自动把所有中间运算限制为 8 位。

### 16.7 用 GDB 验证，而不是只相信推导

先验证成功、失败两种完整行为和退出码：

```text
$ printf 'Meze42\n' | ./validator; code=$?; printf 'exit=%d\n' "$code"
input: correct
exit=0

$ printf 'AAAAAA\n' | ./validator; code=$?; printf 'exit=%d\n' "$code"
input: wrong
exit=1
```

```gdb
set disassembly-flavor intel
break check
run
x/s $rdi
disassemble /r check
```

从反汇编找到循环开头的当前地址，设置断点：

```gdb
break *LOOP_ADDRESS
continue
info registers

# 按当前 disassemble 输出，找出输入/key/target 的真实基址表达式后再查看：
x/6bx INPUT_BASE
x/6bx KEY_BASE
x/6bx TARGET_BASE
```

前面的教学整理版使用 `rbx/r8/r9` 作为这三个基址，但由 `validator.c` 真实编译出的基线可能使用栈槽或其他寄存器。以当前 `disassemble /r check` 为准，把上面的占位表达式替换掉。用错误输入时，单步到当前构建中真正比较变换字节与目标字节的指令，确认哪一轮首次不等；用 `Meze42` 再运行，确认六轮都通过并令返回值为 1。最后把答案交给完整程序，记录成功文本和退出码。

`LOOP_ADDRESS` 必须从你当前构建的反汇编取得；编译器版本、PIE 和优化选项变化后，硬编码的绝对地址不可靠。

### 16.8 优化并 strip 后怎样继续

可以把同一源码构建成：

```bash
gcc -O2 validator.c -o validator_O2
cp validator_O2 validator_stripped
strip validator_stripped
```

你可能看到：

- `check` 名字消失；
- 循环被展开或部分合并；
- 常量通过不同宽度加载；
- `strlen` 检查与后续逻辑被内联/重排；
- `rbp` 栈帧消失。

但语义不变量仍在：成功条件最终仍依赖输入和这些常量所表达的信息。优化器可能合并、折叠或重新编码 key/target，使两张六字节数组不再以原形存在；逆向的核心是追踪等价的数据依赖，而不是寻找与教学版完全相同的数组或指令形状。

## 17. CTF Reverse 的可复用工作流

### 17.1 第一步：建立样本事实表

先记录而不是猜：

```text
哈希：
文件格式：ELF / PE / 其他
架构与位数：
大小端：
入口点：
是否有符号：
装载映射与权限：
PIE/重定位相关属性：
导入与依赖：
可见字符串：
运行需要的参数、文件、环境：
```

对未知文件的运行观察应放在可恢复、隔离的环境中，并记录输入、输出和退出码，避免让环境差异污染推断。

### 17.2 找到输入、成功条件和失败条件

常见入口线索：

- `scanf/fgets/read/GetDlgItemText/...` 等输入 API；
- `strcmp/memcmp/strlen` 等比较与长度 API；
- `correct/wrong` 等输出字符串交叉引用；
- `main/WinMain` 或框架回调；
- 导入函数的调用点。

但这些只是导航。最终要回答：

> 哪一个条件决定成功基本块可达？这个条件的数据从输入经过了哪些变换？

### 17.3 向后切片和向前追踪结合

从成功分支向后：

1. 成功前最后一次 `cmp/test` 比较什么；
2. 两侧值由哪些指令定义；
3. 哪些循环或函数生成这些值；
4. 哪些字节最终来自用户输入。

从输入向前：

1. 输入缓冲区地址在哪里；
2. 长度如何计算；
3. 每次读取的偏移和宽度；
4. 数据经过 XOR、加减、查表、旋转还是函数调用；
5. 结果在哪里比较。

两条链在关键比较处闭合，能降低漏掉中间状态的概率。

### 17.4 给语义命名

把：

```text
sub_401230 → read_input
sub_4012A0 → transform_byte
sub_401340 → verify_input
v7         → input_index
v11        → transformed_byte
```

命名是分析工具，不是结论。证据变化时及时改名。比起 `temp1/temp2`，写清“值从哪里来、准备到哪里去”更有帮助。

### 17.5 先写伪代码，再写求解器

求解脚本必须忠实保留：

- 位宽；
- 符号扩展或零扩展；
- 模运算；
- 大小端；
- 循环边界；
- 数组索引；
- C 整数提升；
- 比较采用 signed 还是 unsigned。

能直接逆变换就写普通 Python；多个变量受联立约束时再考虑 Z3；路径数量巨大且难以手动建模时再评估符号执行。工具不会替你纠正错误的位宽和条件。

### 17.6 静态结论用动态实验验证

优秀的动态断点回答具体问题：

- 在第 5 轮循环停下，`i` 是否真是 4？
- `[base+i*4]` 的 4 字节是否符合数组假设？
- `jne fail` 前 `ZF` 为什么是 0？
- 间接调用目标是否总落在同一只读表列出的代码地址？
- 某字段是否在构造时写入、之后只读？

一次可证伪实验胜过十次“看起来像”。

### 17.7 patch 的正确定位

修改条件跳转可以帮助验证：“如果绕过这里，后面是否还有第二层检查？”但直接改成成功分支通常只证明控制流位置，不会自动给出真正输入。

如需 patch，应记录：

- 虚拟地址与文件偏移如何换算；
- 原字节和新字节；
- 指令长度是否一致；
- 校验和、签名或自校验是否受影响；
- 原文件备份和恢复方法。

把 patch 当实验工具，不要让它替代数据流理解。

### 17.8 常见错误路线

1. **逐行翻译却不画控制流**：会在跳转中迷路；
2. **只看伪代码**：容易错过宽度、标志和间接引用；
3. **只看汇编不重命名**：短期记忆很快耗尽；
4. **看到 XOR 就猜加密**：单一指令没有算法身份；
5. **忽略 signed/unsigned**：边界条件会完全相反；
6. **忽略 `eax` 写入清高位**：容易虚构不存在的高位依赖；
7. **把 `lea` 总翻成取地址**：会误读普通整数算术；
8. **把 `[base+offset]` 必定当结构体**：也可能是数组、缓冲区或上下文块；
9. **把反编译器类型当事实**：错误类型会传染整个伪代码；
10. **过早上自动化**：错误模型只会更快地产生错误答案。

## 18. 学习规划：以能力检查点而不是背诵天数推进

### 阶段 A：值、地址和单条指令

完成标准：

- 能用自己的话解释 `p`、`*p`、`&p`；
- 能画出一个 `int[3]` 的地址和字节；
- 能手算 `[base+index*scale+disp]`；
- 能说出指令读写几字节；
- 能解释 `mov eax,...` 对 `rax` 高位的影响。

练习材料只需要 5—10 行 C 函数，不做完整题。

### 阶段 B：条件、循环和函数

完成标准：

- 能区分 `jg` 与 `ja`；
- 能从跳转画出基本块和循环回边；
- 能在 System V 函数入口指出前六个整数参数位置；
- 能在栈上找到返回地址；
- 能解释 caller-saved/callee-saved，而不是死背所有寄存器。

### 阶段 C：数据布局与工具

完成标准：

- 能从 scale 推测数组元素宽度，并说出替代解释；
- 能从多个偏移逐步恢复结构体；
- 能用 GDB 同一地址按字节、dword、qword 和字符串观察；
- 能把静态地址转换为本次运行的模块内地址；
- 能在 IDA/Ghidra 修正签名、重命名并验证伪代码。

### 阶段 D：完整基础题

完成标准：

- 从输入函数或失败字符串定位验证逻辑；
- 独立恢复长度、循环和每字节变换；
- 写 Python 复现正向逻辑和逆向求解；
- 把答案交回原程序，记录字面输出与退出码；
- 能解释为什么答案正确，而不只是“脚本跑出来了”。

### 阶段 E：优化代码和 C++

完成标准：

- 对比同一源码 `-O0/-O2`，识别变量消失、内联和分支改写；
- 能识别 `this` 候选和常见简单虚表模式；
- 知道 ABI 实现细节不是 C++ 语言永久布局保证；
- 面对 STL/异常运行库能先隔离业务逻辑而非陷入库内部。

### 之后再扩展

基础闭环稳定后，再按题目需要学习：

- Z3 约束求解；
- angr 等符号执行；
- 常见编码、哈希和密码算法实现；
- 反调试、混淆、壳和自修改代码；
- VM 类题目与自定义字节码；
- ARM64、WebAssembly 或其他架构；
- 漏洞利用与逆向交叉知识。

这些不是读懂第一批 x86-64 C/C++ 验证器的前置条件。

## 附录 A：常用指令速查

速查表用于忘记时回看，不代替正文中的状态模拟。

| 类别 | 指令 | 核心语义 | 重要提醒 |
|---|---|---|---|
| 传送 | `mov dst, src` | 复制值 | 一般不同时用两个普通内存操作数 |
| 地址 | `lea dst, [addr]` | 计算有效地址 | 不访问 `addr` 指向的内存，不改标志 |
| 零扩展 | `movzx dst, src` | 小宽度无符号扩展 | 高位补 0 |
| 符号扩展 | `movsx dst, src` | 小宽度有符号扩展 | 高位复制符号位 |
| 32→64 符号扩展 | `movsxd r64, r/m32` | 32 位有符号数变 64 位 | 常见于有符号索引 |
| 加减 | `add/sub dst, src` | `dst +=/-= src` | 更新算术标志 |
| 增减 | `inc/dec dst` | 加/减 1 | 不修改 CF，其他相关标志可变 |
| 取负 | `neg dst` | `dst = 0 - dst` | 不是 `not` |
| 按位取反 | `not dst` | 每一位翻转 | 不等于算术取负 |
| 乘 | `imul` | 有符号乘法的多种形式 | 注意结果宽度和具体形式 |
| 无符号除 | `div src` | 高低拼接被除数 ÷ src | 商/余数位置随操作数宽度固定 |
| 有符号除 | `idiv src` | 有符号除法 | 常见前置 `cdq/cqo` |
| 位与 | `and dst, src` | 按位 AND | 掩码、对齐、截断 |
| 位或 | `or dst, src` | 按位 OR | 设置某些位 |
| 位异或 | `xor dst, src` | 按位 XOR | `xor eax,eax` 常清零 |
| 左移 | `shl/sal dst, n` | 位左移，低位补 0 | 保留宽度内结果 |
| 逻辑右移 | `shr dst, n` | 高位补 0 | 常见无符号语义 |
| 算术右移 | `sar dst, n` | 高位复制符号位 | 不能无条件等同 C 有符号除法 |
| 循环移位 | `rol/ror dst, n` | 移出的位绕回另一端 | 哈希/混淆常见，但不是唯一证据 |
| 比较 | `cmp a, b` | 按 `a-b` 更新标志 | 不保存差值 |
| 测试 | `test a, b` | 按 `a&b` 更新标志 | 不保存 AND 结果 |
| 跳转 | `jcc label` | 条件成立时改变 RIP | 条件来自最近的相关标志定义 |
| 置布尔 | `setcc r/m8` | 条件成立写 1，否则写 0 | 只写 1 字节 |
| 条件传送 | `cmovcc dst, src` | 条件成立时替换目标的相应宽度 | 内存源在条件假时也可能被访问；32 位目标仍有清高 32 位规则 |
| 入栈 | `push src` | 常见 64 位形式使 `rsp-=8` 并写栈 | 具体编码和操作数形式需查手册 |
| 出栈 | `pop dst` | 读 `[rsp]` 后 `rsp+=8` | 与保存顺序配对 |
| 调用 | `call target` | 压返回地址并转移控制 | 参数规则来自 ABI |
| 返回 | `ret` | 从栈取返回地址给 RIP | 栈损坏会影响控制流 |
| 栈帧收尾 | `leave` | 近似 `mov rsp,rbp; pop rbp` | 只适合对应帧形态 |
| 字节交换 | `bswap reg` | 反转寄存器内字节顺序 | 常见于大小端转换 |
| 无操作 | `nop` | 不改变普通计算状态 | 填充、对齐、patch 空间 |

字符串指令示例：

```asm
rep movsb
```

指令自身固定使用 `rsi` 作为源、`rdi` 作为目的、`rcx` 作为计数，并受方向标志影响。这是 ISA 的隐式操作数规则；函数入口参数是否一开始就在这些寄存器，仍由 ABI 和前置搬运决定。

## 附录 B：条件跳转与标志速查

假设前面执行 `cmp a, b`：

| 条件 | 跳转 | 标志条件 |
|---|---|---|
| 相等 | `je/jz` | `ZF = 1` |
| 不等 | `jne/jnz` | `ZF = 0` |
| 无符号 `a > b` | `ja` | `CF = 0 && ZF = 0` |
| 无符号 `a >= b` | `jae` | `CF = 0` |
| 无符号 `a < b` | `jb` | `CF = 1` |
| 无符号 `a <= b` | `jbe` | `CF = 1 \|\| ZF = 1` |
| 有符号 `a > b` | `jg` | `ZF = 0 && SF = OF` |
| 有符号 `a >= b` | `jge` | `SF = OF` |
| 有符号 `a < b` | `jl` | `SF != OF` |
| 有符号 `a <= b` | `jle` | `ZF = 1 \|\| SF != OF` |
| 结果为负号位 | `js` | `SF = 1` |
| 结果无负号位 | `jns` | `SF = 0` |
| 有符号溢出 | `jo` | `OF = 1` |
| 无有符号溢出 | `jno` | `OF = 0` |

别名关系：`je` 与 `jz` 检查同一条件，`jne` 与 `jnz` 也一样；不同名字用于表达不同语境。

## 附录 C：两套 x86-64 ABI 最小对照

| 项目 | Linux 等常见 System V AMD64 | Windows Microsoft x64 |
|---|---|---|
| 整数/指针参数 | `rdi,rsi,rdx,rcx,r8,r9` | `rcx,rdx,r8,r9` |
| 整数/指针返回 | `rax` | `rax` |
| 常见非易失整数寄存器 | `rbx,rbp,r12-r15` | `rbx,rbp,rdi,rsi,r12-r15` |
| 普通调用的栈对齐 | 执行 `call` 前 `rsp % 16 == 0`；刚进入被调函数时通常 `rsp % 16 == 8` | 同左；非叶函数在序言/尾声之外维持 16 字节对齐 |
| red zone | 用户态通常有 128 字节 | 无 |
| shadow space | 无 Windows 式固定 32 字节 | 调用者预留 32 字节 |
| 常见文件格式 | ELF | PE |
| 外部导入机制关键词 | PLT/GOT、重定位 | IAT、重定位 |

这张表只覆盖入门整数/指针情况，不覆盖可变参数、复杂结构体返回、向量、异常展开和所有浮点分类。

表中的 64 位寄存器名表示参数槽；实际读取宽度仍由参数类型决定。例如 32 位 `int` 应读取对应的 `edi/esi/edx/...`，多余高位没有参数语义。

## 附录 D：GDB 查看格式

`x/NFU ADDRESS`：

- `N`：数量；
- `F`：显示格式，如 `x` 十六进制、`d` 十进制、`s` 字符串、`i` 指令；
- `U`：单位，如 `b` 1 字节、`h` 2 字节、`w` 4 字节、`g` 8 字节。

例子：

| 命令 | 含义 |
|---|---|
| `x/16bx $rdi` | 从 `rdi` 开始看 16 个字节，十六进制 |
| `x/4wx $rsp` | 从栈顶看 4 个 4 字节值 |
| `x/8gx $rsp` | 从栈顶看 8 个 8 字节值 |
| `x/s $rax` | 把 `rax` 指向的内容按 C 字符串显示 |
| `x/10i $rip` | 从当前指令起反汇编 10 条 |
| `p/x $rax` | 把寄存器值按十六进制打印 |

同一地址换不同单位查看，是训练“内存只有字节、类型来自解释”的最佳方式之一。

## 附录 E：AT&T 语法只需先会辨认

GNU 工具有时默认输出 AT&T 语法。本文不混用，只给最小对照：

| Intel | AT&T | 差异 |
|---|---|---|
| `mov eax, edi` | `movl %edi, %eax` | AT&T 是源在前、目的在后 |
| `add eax, 4` | `addl $4, %eax` | 寄存器有 `%`，立即数有 `$` |
| `mov eax, [rdi+rcx*4]` | `movl (%rdi,%rcx,4), %eax` | 内存写成 `disp(base,index,scale)` |
| `mov rax, [rbp-8]` | `movq -8(%rbp), %rax` | `b/w/l/q` 常表示 1/2/4/8 字节 |

学习和调试时可统一设置 Intel：

```gdb
set disassembly-flavor intel
```

## 附录 F：综合练习

### 练习 1：子寄存器

已知 `rax = 0x1122334455667788`：

1. 执行 `mov al, 0xAA` 后 `rax` 是多少？
2. 随后执行 `mov eax, 1` 后 `rax` 是多少？

### 练习 2：小端

内存低地址到高地址为：

```text
EF BE AD DE 00 00 00 00
```

按 32 位小端整数读取前四字节是多少？按 64 位读取八字节是多少？

### 练习 3：指针与数组

`int32_t a[5]` 从 `0x5000` 开始。`&a[4]` 是多少？`a+5` 的数值是多少？后者能否被合法解引用为数组元素？

### 练习 4：有效地址

`rdi=0x1000`、`rsi=3`，计算 `[rdi+rsi*4+0x10]`。如果指令是 `movzx eax, byte ptr [...]`，实际读几字节？

### 练习 5：signed 与 unsigned

`eax=0xFFFFFFFF`、`ecx=1`，执行 `cmp eax,ecx` 后，`jl` 与 `ja` 哪些成立？分别如何解释？

### 练习 6：恢复循环

```asm
xor eax, eax
xor ecx, ecx
loop:
    add eax, dword ptr [rdi + rcx*4]
    inc rcx
    cmp rcx, rsi
    jb loop
ret
```

写出一份等价伪代码，并指出对 `rsi=0` 时这段汇编是否安全表达常见 `for(i=0;i<n;i++)`。

### 练习 7：调用约定

System V 下进入 `f(int *p, size_t n, int value)` 时，三个参数通常在哪？Windows x64 又在哪？

### 练习 8：间接调用

解释 `call rax` 与 `call [rax]` 的目标地址分别怎样取得。

### 练习 9：结构体候选

某基址 `rbx` 出现：

```asm
movzx eax, byte ptr [rbx]
mov   ecx, dword ptr [rbx+4]
mov   rdx, qword ptr [rbx+8]
```

提出一个可能结构，但同时列出至少两项仍需验证的证据。

### 练习 10：逆变换

某字节满足：

```text
y = rol8(x XOR 0x5A, 3)
```

写出求 `x` 的操作顺序。`rol8` 表示严格 8 位循环左移。

## 附录 G：综合练习答案

### 答案 1

`mov al,0xAA` 只改最低字节：`rax = 0x11223344556677AA`。写 `eax=1` 清高 32 位：`rax = 0x0000000000000001`。

### 答案 2

前四字节是 `0xDEADBEEF`；八字节是 `0x00000000DEADBEEF`。

### 答案 3

每个 `int32_t` 4 字节，`&a[4] = 0x5010`，`a+5 = 0x5014`。C/C++ 允许形成尾后指针用于比较和差值，但不能把它解引用成有效数组元素。

### 答案 4

地址是 `0x1000 + 3*4 + 0x10 = 0x101C`。`byte ptr` 只读 1 字节，`movzx` 再把它零扩展。

### 答案 5

两个都成立：有符号看 `-1 < 1`，所以 `jl`；无符号看 `4294967295 > 1`，所以 `ja`。

### 答案 6

候选伪代码：

```c
uint32_t sum(const uint32_t *a, size_t n) {
    uint32_t s = 0;
    size_t i = 0;
    do {
        s += a[i];
        ++i;
    } while (i < n);
    return s;
}
```

由于第一次检查发生在循环体之后，`n=0` 时仍会读取 `a[0]`。所以它不能直接等价于常见的前测 `for(i=0;i<n;i++)`，除非调用前提保证 `n>0`，或前面还有未展示的零长度检查。

### 答案 7

System V：`rdi=p`、`rsi=n`、`edx=value`。Windows x64：`rcx=p`、`rdx=n`、`r8d=value`。这里的 `int` 都按低 32 位读取；不要把完整 `rdx/r8` 的高 32 位当作已经完成符号扩展的参数值。

### 答案 8

`call rax` 直接把 `rax` 的值作为目标；`call [rax]` 先从 `rax` 指向的内存读取一个目标地址，再调用它。

### 答案 9

一种候选：

```cpp
struct Candidate {
    uint8_t tag;      // offset 0
    // padding 1..3
    uint32_t count;   // offset 4
    void *data;       // offset 8
};
```

仍需验证：分配/步长是否符合结构体总大小；偏移 8 的值是否真的作为合法地址解引用；偏移 4 是否参与无符号 32 位运算；其他函数是否以相同布局访问；是否存在打包或数组解释。

### 答案 10

逆序执行：先做 8 位循环右移 3 位，再异或同一密钥。

```text
x = ror8(y, 3) XOR 0x5A
```

## 最后的方法总结

遇到任何陌生汇编片段，按这个顺序问：

1. **状态**：当前已知的寄存器、内存和标志是什么？
2. **宽度**：每次读写 1、2、4 还是 8 字节？
3. **地址**：方括号内的有效地址怎么算？这是值、地址还是地址中的内容？
4. **符号**：扩展、比较、移位和除法采用有符号还是无符号语义？
5. **控制流**：条件从哪条指令产生，跳向哪个基本块，有没有回边？
6. **ABI**：参数、返回值和需保存寄存器遵循哪套调用约定？
7. **数据布局**：固定偏移、步长和访问宽度支持哪些数组/结构体假设？
8. **证据层级**：这是 ISA 事实、ABI 规则、编译器常见形态，还是待验证的逆向假设？
9. **动态验证**：用哪一个断点或内存观察能最快证伪当前假设？
10. **闭环**：复现脚本能否正向得到目标，求出的输入能否被原程序接受？

真正需要形成的不是“看过很多指令”，而是把每条指令当成精确的状态变化，再把连续状态变化组织成数据流和控制流。做到这一点，反编译器、调试器和求解器才会从黑盒按钮变成你能判断、修正和验证的工具。
