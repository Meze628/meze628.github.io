## 前置基础

### 关于整体思路

我们平时在一台设备上，尤其是 Windows/Linux 设备上编写程序后，如何在操作系统中运行？
```texr
C/C++ 源码
   │  编译器：翻译并优化
   ▼
汇编 / 机器指令
   │  汇编器、链接器：生成可执行文件并连接外部函数
   ▼
磁盘上的 ELF 或 PE 文件（以机器码的形式运行）
   │  操作系统加载器：映射代码和数据，准备栈与依赖库
   ▼
进程：拥有自己的虚拟地址空间和一组正在变化的 CPU 状态
```

这里主要探讨汇编，汇编本质是机器码的人类可读形式，机器码只包含 0 和 1。程序本质上是在使用 CPU 进行运算并操控内存和 CPU 里的寄存器。

不同硬件对应的汇编建构是不同的，同一种汇编架构也有不同的语法。

| 架构 | 通常位数 | 整数寄存器 | 指令长度 | 常见平台 |
|---|---:|---:|---|---|
| **x86-32 / IA-32** | 32 位 | 8 个通用寄存器 | 1～15 字节，可变长度 | 老式 Windows、Linux PC、部分嵌入式设备 |
| **x86-64 / AMD64** | 64 位 | 16 个通用寄存器 | 1～15 字节，可变长度 | Windows、Linux PC、服务器 |
| **AArch64 / ARM64** | 64 位 | 31 个通用整数寄存器 | 固定 4 字节 | Android、iPhone、Apple Silicon、服务器 | 移动端逆向最重要 |
| **ARM32** | 32 位 | 名义上 16 个，约 13 个可自由使用 | ARM 指令4字节；Thumb 指令2或4字节 | 老款手机、嵌入式设备 |
| **MIPS** | 32/64 位 | 32 个，其中1个恒为0 | 通常固定4字节 | 路由器、摄像头、IoT 设备 |
| **RISC-V** | 32/64 位最常见 | 32 个，其中1个恒为0 | 基础指令4字节，压缩指令2字节 | 新型嵌入式设备、教学和芯片研发 |

这里位数表示每个寄存器的位数

### 关于数据

数据以二进制形式存储，位表示二进制数当中的每一位，$1$ 位只能是 `0` 或 `1`，$1$ 字节（byte）就是 $8$，位数就是长度，之后有如下单位：

|单位|长度|无符号范围|有符号范围|
|---|---|---|---|
|bit|$1$|$0$ ~ $1$|/|
|byte（字节）|$8$| $0$ ~ $255$ | $-128$ ~ $127$ |
|word（字）|$16$| $0$ ~ $65535$ | $-2^{15}$ ~ $2^{15}-1$ |
|dword（双字）|$32$| $0$ ~ $2^{32}-1$ | $-2^{31}$ ~ $2^{31}-1$ |
|qword（四字）|$64$| $0$ ~ $2^{64}-1$ | $-2^{63}$ ~ $2^{63}-1$ |

常常以十六进制表示长的二进制，一位十六进制就是四位二进制。    

#### 关于无符号数、有符号数、位数扩展、溢出、补码与反码

无符号数就是非负整数，例如 `0xff` 就表示 $255$。     

有符号整数可以表示负数，这时，这个数的最高位不在表示数值，而是表示符号，最高位是 $1$ 表示是负数，是 $0$ 表示正数。如果说有 $n$ 位，表示负数时，第 $n$ 位为 $1$，前 $n-1$ 位表示为 $k$ 时，这个数整体表示为 $k-2^n$，例如有符号数 `0xff` 表示 $-1$。

正数的反码是各位按位取反，对于每一位，$1$ 变成 $0$，$0$ 变成 $1$，
负数的反码就是对除了符号位的个位数取反。
负数的补码是其反码再加 $1$

关于位数扩展：    
无符号数在高位补 $0$，成为零扩展。     
有符号数在高位补上符号位（就是整数补 $0$，负数补 $1$），是整数时显而易见。是负数时，考虑证明，不妨设从 $m$ 位扩展到 $n$ 位，原数是 $k-2^m$，扩展后的数是

$$
\begin{aligned}
k+\sum_{i=m}^{n-1}2^i-2^n &= k+(2^m-1-k)-(2^m-1-k)+\sum_{i=m}^{n-1}2^i-2^n \\
&= \sum_{i=1}^{n-1}2^i-2^n+1+k-2^m \\
&= k-2^m
\end{aligned}
$$

得证。    

关于溢出，可以用一个数学式子表达，当 $a+b$ 的结果无法使用他们数据类型容下时，其真正的结果应当是 $(a+b) \mod{2^n}$。本质就是在数据范围内循环。
有符号数的溢出也是在其数据范围内的循环，但在许多编程语言里，有符号数的溢出属于未定义行为。


## x86-64 汇编
### 寄存器
#### 通用寄存器

x86-64 有 16 个 64 位通用寄存器。同一个寄存器可以用不同名称访问低 32 位、16 位或 8 位；表中的用途是常见约定，并非寄存器永久固定的功能。

| 64 位 | 32 位 | 16 位 | 8 位 | 常见用途 |
|---|---|---|---|---|
| `RAX` | `EAX` | `AX` | `AL` / `AH` | 计算结果、函数返回值，乘除法中有特殊用途 |
| `RBX` | `EBX` | `BX` | `BL` / `BH` | 通用数据，调用约定中通常需要被调用函数保存 |
| `RCX` | `ECX` | `CX` | `CL` / `CH` | 函数参数、循环计数，`CL` 常保存移位次数 |
| `RDX` | `EDX` | `DX` | `DL` / `DH` | 函数参数，乘除法中与 `RAX` 配合 |
| `RSI` | `ESI` | `SI` | `SIL` | 通用数据，字符串指令中的源地址 |
| `RDI` | `EDI` | `DI` | `DIL` | 通用数据，字符串指令中的目标地址 |
| `RBP` | `EBP` | `BP` | `BPL` | 通用数据，未优化代码中常作为栈帧基准 |
| `RSP` | `ESP` | `SP` | `SPL` | 栈顶指针，不应当作普通临时寄存器随意使用 |
| `R8` | `R8D` | `R8W` | `R8B` | 函数参数或临时数据 |
| `R9` | `R9D` | `R9W` | `R9B` | 函数参数或临时数据 |
| `R10` | `R10D` | `R10W` | `R10B` | 临时数据 |
| `R11` | `R11D` | `R11W` | `R11B` | 临时数据 |
| `R12` | `R12D` | `R12W` | `R12B` | 通用数据，通常需要被调用函数保存 |
| `R13` | `R13D` | `R13W` | `R13B` | 通用数据，通常需要被调用函数保存 |
| `R14` | `R14D` | `R14W` | `R14B` | 通用数据，通常需要被调用函数保存 |
| `R15` | `R15D` | `R15W` | `R15B` | 通用数据，通常需要被调用函数保存 |

具体哪些寄存器用于传参、哪些必须保存，由操作系统和调用约定决定。

#### 特殊寄存器

| 寄存器 | 作用 |
|---|---|
| `RIP` | 指令指针，保存下一条将要执行的指令地址 |
| `RFLAGS` | 标志寄存器，保存零、进位、符号、溢出等运算状态 |
| `FS` / `GS` | 段寄存器；现代 x86-64 系统常借助其基址访问线程局部存储等数据 |
| `CR0`～`CR4`、`CR8` | 控制寄存器，供操作系统管理分页、保护模式等，普通用户程序不能随意访问 |
| `DR0`～`DR7` | 调试寄存器，用于实现硬件断点 |

64 位兼容 32 位及更低位

```
位号：63                           32 31           16 15        8 7         0
RAX ：[---------------------------完整 64 位--------------------------------]
EAX ：                                  [-----------低 32 位----------------]
 AX ：                                                      [---低 16 位----]
 AH ：                                                      [15......8]
 AL ：                                                                 [7..0]
```

#### 关于寄存器的汇编操作

例如一段如下 C++ 代码
```cpp
int x = 3;
int y = 4;
int result = (x + y) * 2;
```
可以用汇编表示成
```asm
mov eax, 3          ; eax = 3
mov ecx, 4          ; ecx = 4
add eax, ecx        ; eax = 3 + 4
add eax, eax        ; eax = 2 * (3 + 4)
```
汇编中一行命令的分号后面为注释，这里就是 `mov` 和 `add` 在寄存器里的简单应用

但是有一点特殊的是，在 x86-64 中：

```asm
mov eax, 1
```

执行后整个 `rax` 是 `0x0000000000000001`。写入 `eax` 会自动把 `rax` 的高 32 位清零。

但写 `ax` 或 `al` 不会自动清除其余位：

```asm
; 假设 rax = 0x1122334455667788
mov al, 0xFF
; 结果 rax = 0x11223344556677FF
```

所以看到 `xor eax, eax` 时，它常用于把完整 `rax` 清零：

```asm
xor eax, eax        ; eax = 0，因此 rax 也变成 0
```
